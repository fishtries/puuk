# Album merge and manual-credit coordination

The file-backed album PATCH now holds a shared, database-scoped coordination lock from before its initial reads and merge preflight until the file mutations, final merge or partial split, and response construction finish. Track/album credit PUT and legacy adapter share the same lock, as do bulk apply and undo, before any SQLite write transaction; bulk preview does not alter manual decisions and is not serialized. The guard is reentrant on the same thread, so an album legacy credits-only PATCH can call the PUT service without deadlocking. It does not hold a SQLite transaction across file operations or change the underlying album merge rules.

`brain/services/artist_credit_lock.py` keys a process-local RLock and Linux `flock` by the canonical SQLite path. The coordination file is a stable SHA-256 pathname in `/var/tmp/puuk-artist-credit-locks-v2`, outside `MUSIC_DIR`, and the combined thread/process acquisition budget is five seconds. Lock contention or inability to open the shared lock namespace fails closed with HTTP 503 `credits_busy` and `Retry-After: 1`; the stable lock file must never be unlinked while any writer is running. The sticky shared directory and readable lock inode let processes under different UIDs lock the same inode when permissions permit; otherwise they fail closed. O_NOFOLLOW, regular-file checking and nonblocking open avoid following a substituted symlink or blocking on a FIFO.

The guarantee assumes all SQLite writers run on the same host and share the same `/var/tmp` mount namespace and canonical database path, use these guarded application entry points, and that system cleanup or operators do not remove lock files while services are active. Runtime users need access to the shared directory and lock inode; using the same UID is the simplest supported deployment. Direct SQL or old application binaries bypass the guard, so the existing requirement to stop old writers during rollout remains. Different containers or hosts with private `/var/tmp` do not coordinate; a shared lock namespace would be required before such a deployment. The guard deliberately fails if `/var/tmp` itself lies inside the configured music directory.
