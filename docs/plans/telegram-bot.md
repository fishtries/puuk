# Новый Telegram-бот Puuk

Цель — прислать ссылку на трек, альбом или плейлист и получить именно выбранную запись. Основной сценарий для медиатеки — перенести целый альбом в Puuk, открыть его на телефоне и пополнить каталог для «Моей Волны». Второй вход — прислать собственные аудиофайлы, включая комплект дисков одного издания.

## Что выбрано

- Первые площадки — YouTube, SoundCloud, Spotify и VK Музыка. Следующая названная площадка — Яндекс Музыка. В перспективе пользователь хочет отправлять ссылки с любого привычного стриминга.
- Поддержать ссылки на треки, альбомы и плейлисты. Отправленный в чат MP3, FLAC, M4A или ZIP с альбомом сразу запускает импорт в Puuk. Подпись и выбор назначения для вложения не требуются. Сохранённый режим действует только на ссылки.
- Для автоматического получения аудио использовать только бесплатные источники. Если нужный файл недоступен, сохранить позицию в отчёте для добора.
- Условие приёмки для *MILITANTUM* — 17 из 17 альбомных записей за один автоматический запуск, ноль обнаруженных подмен. Пользователь один раз отправляет ссылку Spotify в режиме «В Puuk». Бот сам проверяет звук и при расхождении пробует другой источник.
- Импортировать оригинальные файлы и заполнять существующие поля каталога Puuk. После подтверждения издания автоматически дополнять пустые поля данными из проверенного источника. При расхождении с тегом файла дать пользователю выбрать значение.
- Пользователь один раз выбирает «В Puuk» (на сервер) или «В Telegram» для обычных ссылок. Бот запоминает выбор между запусками. Команда `/tg <ссылка>` в одном сообщении отправляет треки по этой ссылке в чат по порядку. Для разового импорта на сервер предусмотрена парная команда `/puuk <ссылка>`. Следующая обычная ссылка снова использует сохранённый режим.
- Альбом в режиме «В Telegram» приходит без звука уведомлений. Сообщение о загрузке и каждый файл, начиная с первой песни, отправлять с `disable_notification=true`. Это относится и к трекам, полученным при доборе. [Параметр тихой отправки в Telegram Bot API](https://core.telegram.org/bots/api#sendaudio)
- Если пользователь прислал отдельную песню, пока загружается его плейлист, взять её при первой возможности. При свободном месте загрузка начинается сразу. Если все места заняты, уже начатые файлы догружаются и первое освободившееся место получает одиночная песня. Её результат доставить в выбранном для этой ссылки режиме. Импорт плейлиста продолжается автоматически с сохранением порядка его треков.
- Если по ссылке с назначением «В Telegram» найден FLAC, отправлять его документом в исходном качестве. В альбоме каждый FLAC приходит отдельным файлом на своей позиции.
- Ботом пользуются все, у кого Telegram ID привязан к аккаунту Puuk. Каждое задание, нажатие и изменение медиатеки выполняется от имени этого пользователя.
- Каталог для прослушивания и «Волны» общий. После импорта на сервер кнопка с сердцем сохраняет альбом или обычный плейлист в личную медиатеку, а одиночный трек — в «Избранное».
- Обычный внешний плейлист импортировать как приватный плейлист в аккаунте пользователя Puuk. У подборки, которую создал сам Spotify, импортировать только подтверждённые треки в общий каталог для прослушивания и «Волны». Избранное пользователь пополняет сам.
- В приватном плейлисте сохранять каждое появление одной и той же записи на своём месте. Если песня стоит на 3-м и 12-м местах, в Puuk она прозвучит дважды. Обе позиции используют один трек каталога и один аудиофайл.
- В первой версии пользователь присылает ссылку на плейлист Spotify без подключения своего аккаунта Spotify. Импорт доступен, когда бот может прочитать состав по ссылке. Если список недоступен, бот объясняет это в чате.
- В первой версии пользователь присылает ссылку «Поделиться» из VK Музыки на плейлист, который сможет открыть другой человек. Бот получает состав по этой ссылке без подключения личного аккаунта VK владельца. Перед созданием приватной копии в Puuk сверяет полноту списка.
- Для трека, альбома и плейлиста VK единственный источник звука — конкретная загрузка в VK. В режимах «В Puuk» и «В Telegram» сохранять полный файл. Фрагментированный MP4, у которого не читается длительность, перепаковывать в M4A без перекодирования. Метаданные для карточки хранить в Puuk. Если файл недоступен, показать причину у его позиции.
- Повторная отправка того же альбома обновляет его данные. При подборе аудио по релизу, например из Spotify, уже сохранённый пользовательский FLAC нужной записи с этого издания имеет приоритет над найденным MP3.
- Перед обновлением приватной копии показать владельцу предстоящие изменения. После одного нажатия «Обновить» расставить песни из источника в порядке автора, даже если владелец копии переставлял их вручную. Его личные добавления и удаления сохраняются. Песня, которую он вставил после конкретного трека, перемещается вместе с этим вхождением. Если автор удалил этот трек, личная песня сохраняет место между оставшимися соседями. Владелец может вернуть удалённую им песню, снова добавив её в свою копию.
- Если в каталоге под альбомным треком обнаружилась подтверждённая другая версия, сразу снять ошибочную запись с воспроизведения под этим названием и исключить её из «Волны». Позиция остаётся в отчёте импорта для добора оригинала.
- При импорте на сервер альбом появляется в Puuk с первым готовым треком. Каждый следующий подтверждённый трек доступен сразу на своей позиции в том же альбоме.
- Ориентир для выбора звука — версия по ссылке. Под студийным треком должен играть студийный трек. Если пользователь сам выбрал концерт, ремикс или демо, импортируется именно эта версия.
- Если запрошенный трек помечен Explicit (E), а у подтверждённой альбомной публикации лейбла отметка о цензуре отсутствует, автоматически добавить запись. В сведениях об источнике оставить статус цензуры неизвестным. Явно обозначенная редакция Clean считается другой версией.
- При подборе записи по релизу, если доступен только ремастер, оставить исходную позицию для добора. В отчёте предложить отдельную кнопку «Добавить ремастер» с годом издания, если он известен. При нажатии импортировать явно выбранный ремастер под его фактической версией.
- По ссылке на открытую песню в YouTube или YouTube Music сразу загрузить одну песню в выбранном режиме, даже если ссылка содержит ID плейлиста. Для загрузки всего плейлиста пользователь присылает ссылку на сам плейлист.
- По ссылке на клип YouTube выбрать звук самого видео, включая вступление и монтаж. По кнопке «Найти альбомную версию» искать студийную запись.
- Из прежнего бота ценна выдача одноразовых кодов входа. Сохранить привычные команды `/code` и `/login` и вход с этим кодом в веб и iOS. [Текущая выдача кода](../../tg_music_bot/bot.py) · [Проверка кода в Brain](../../brain/routers/auth.py)

## Два примера, на которых принимаем бота

**MILITANTUM от тёмного принца, по ссылке Spotify.** В списке 17 позиций. Под № 13 «танцуй» с VILLIAN раньше появлялась концертная запись, под № 14 «охота на уток» с ashleyrossmith — гитарная версия. При приёмке сверить звук именно тех файлов, которые воспроизводятся из карточки альбома в Puuk. [Релиз в Spotify](https://open.spotify.com/embed/album/1ejUHnRNibqQjJgE4xoYD0) · [Примеры прежних ошибок](../../tg_music_bot/test_source_selection.py)

У обеих песен есть публикации на канале «тёмный принц — Topic». В описаниях указаны поставщик TRV, альбом и оба исполнителя соответствующей песни. В контрольном прогоне сервер получил обе публикации. Их звук совпал с полученными ботом файлами SoundCloud по всей проверенной длительности. [«танцуй»](https://www.youtube.com/watch?v=z3mEsgaBrR8) · [«охота на уток»](https://www.youtube.com/watch?v=MdB8nuQLSjw)

**Thriller 40, локальное двухдисковое издание 2022 года.** В предоставленной папке 9 FLAC на CD1 и 10 на CD2. Размеры отдельных файлов от 21,4 до 48,1 МБ, всего около 629 МБ аудио. Теги альбома различаются — `Thriller (CD1)` и `Thriller 40 (CD2)`. Все файлы содержат номер диска и дорожки. На первом диске у всех девяти файлов встроена картинка, на втором встроенных картинок нет. В папке есть отдельные изображения, CUE, M3U и сканы. В «The Girl Is Mine» поле исполнителя содержит Michael Jackson with Paul McCartney. Для полного комплекта ожидаем одно издание 2022 года, два диска, 19 исходных файлов, исходную нумерацию, обложку издания и сохранённые сведения о приглашённом исполнителе. Демо на втором диске действительно входят в издание.

Существующая функция Puuk `read_audio_metadata` прочитала все 19 оригиналов. Каждый содержит год 2022, номера диска и дорожки, комментарий, длительность и стереозвук 44,1 кГц. Встроенные поля жанра, текста песни и исполнителя альбома пусты на обоих дисках. Для карточки альбома взять Michael Jackson из сведений об издании. Для «The Girl Is Mine» сохранить исходную подпись дуэта. Отдельные карточки двух исполнителей связывать по подтверждённому списку участников, как предусмотрено в Puuk. Проверять, что повторный импорт с пустым тегом сохраняет уже заполненные данные. [Чтение файлов](../../brain/metadata.py) · [Правила хранения исполнителей](../MULTI_ARTIST_CONTRACT.md)

**Повторный импорт «Billie Jean» из Thriller 40.** После загрузки папки записать ID трека и контрольную сумму FLAC, который воспроизводит Puuk. Для повторного импорта по ссылке подготовить тот же релиз с подтверждённым жанром для пустого поля и с единственным доступным аудио в MP3 для «Billie Jean». После импорта у трека указан этот жанр. Открыть его под прежним ID и проверить, что воспроизводится исходный FLAC с той же контрольной суммой.

## Как получать нужную версию

| Вариант | Как работает | Что получит пользователь |
| --- | --- | --- |
| Файл из указанного источника | Получить полный файл, привязанный к указанной публикации, где площадка предоставляет такую возможность. Присланный пользователем файл тоже однозначно определяет аудио | Мало действий и прямая связь с выбором пользователя. У ссылок, для которых сервис предоставляет только описание, останутся пропуски |
| Подтверждённая запись из другого источника, например для релиза Spotify | Проверить уже известный файл Puuk, затем доступные каталоги. Установить связь найденного аудио с конкретной записью и проверить релиз и версию | Выше полнота альбомов. На поиск и проверку уходит время. У редкого релиза всё ещё возможны пропуски |
| Добор пользователем | Показать спорные или отсутствующие позиции после автоматического прохода. Для одной позиции принять точную ссылку либо собственный файл | Пользователь контролирует результат и может закончить редкий альбом. Ручная работа касается только оставшихся позиций |

Для VK получить файл по идентификатору выбранной аудиозаписи, в том числе для каждой позиции альбома и плейлиста. Связать позицию с исходной ссылкой, идентификатором записи VK и контрольной суммой полученного файла. Готовую копию в Puuk можно переиспользовать при подтверждённом происхождении из той же загрузки и проверке целостности. Две загрузки с одинаковыми названиями могут содержать разный звук. Если VK отдаёт только карточку или фрагмент, оставить номер в отчёте и предложить повторить получение из VK либо прислать исходный файл вручную. У присланного пользователем файла сохранить его фактическое происхождение.

Считать исходником файл, который VK отдаёт слушателю для этой записи. Для MP4 на CDN выбрать поток по манифесту, который получил плеер, и последующим запросам аудиоданных. Проверить полный диапазон и число полученных байтов. При получении проверить формат по содержимому, полноту аудиодорожки и вычислить SHA-256. При перепаковке MP4 сохранить контрольную сумму исходного контейнера в истории импорта. Если полный файл получить не удалось, указать это у позиции. Хранить ссылку на запись и её происхождение. Прежний общий загрузчик запрашивает MP3, встраивает обложку и метаданные. Для файла VK эти операции пропустить. [Настройки прежнего загрузчика](../../tg_music_bot/downloader.py)

Для ссылок, допускающих другую площадку, автоматически пройти первые два способа до первого подтверждённого результата. Ручной добор предложить для оставшихся позиций. Для звука с другой площадки подойдут официальная публикация той же записи от исполнителя или дистрибьютора с совпадающими данными релиза либо файл, подтверждённый сравнением с доступным эталонным звуком. Сопоставлять идентификаторы, полученные от обоих каталогов, состав исполнителей, издание, версию и длительность. Поиск по ISRC сам по себе подтверждает лишь текст запроса. Ремастер иногда сохраняет тот же ISRC, поэтому при выборе точного издания важны и сведения о мастере. У пользовательской перезагрузки с одними лишь тегами оставить позицию для добора. [Правила ISRC](https://isrc.ifpi.org/faqs)

Для альбома, которому требуется подбор записей на другой площадке, начать с поиска того же издания целиком. Один раз сопоставить исполнителя альбома, издание, состав дисков и последовательность записей. Затем взять кандидатов для конкретных позиций и проверить каждого перед публикацией. Индивидуальный поиск запускать для оставшихся позиций. Это особенно важно для *MILITANTUM*, где у двух соседних треков разные приглашённые артисты. Старый загрузчик сначала принимает подходящий по метаданным результат SoundCloud, и только после неудачи обращается к YouTube Music. Приоритет в новом поиске определяется происхождением записи и связью с выбранным изданием. [Подбор в прежнем загрузчике](../../tg_music_bot/source_worker.py)

При импорте записывать исходную ссылку, фактическое происхождение файла, основание совпадения и версию правил проверки. Проверять файл до присвоения ему каталожных данных. При повторной отправке альбома проверить и ранее заполненные позиции, включая файлы из старого бота.

## Как выглядит импорт

1. При первом запуске бот предлагает выбрать назначение для ссылок и получить код входа. Аудиовложению или ZIP с альбомом сразу назначить «В Puuk». Для ссылки взять назначение из команды `/tg` или `/puuk` в том же сообщении, для обычной ссылки — из сохранённой настройки. Записать назначение в задание при его создании. Команда без ссылки показывает пример целого сообщения. Чтобы добавить в каталог альбом, уже полученный через `/tg`, пользователь снова присылает ссылку с назначением «В Puuk».
2. Бот распознаёт площадку и объект. Для альбома или плейлиста получает полный доступный порядок позиций, в том числе следующие страницы. Показывает название, количество позиций и назначение в одном сообщении.
3. В обоих режимах вести прогресс и итог в одном сообщении о загрузке. В нём же менять счётчик, показывать паузу, причину пропуска и доступное действие. При импорте *MILITANTUM* в Puuk после последнего трека, в том числе после добора, показать в этом сообщении «17 из 17», «Открыть альбом» и кнопку сохранения в медиатеку. Хранить ID чата и сообщения вместе с заданием, чтобы обновлять его после перезапуска. В режиме «В Telegram» служебное сообщение сопровождает заказанные аудиовложения.
4. **Альбом в Puuk.** Опубликовать первый проверенный трек и открыть карточку альбома для прослушивания. Каждый следующий готовый трек добавлять в эту карточку с исходным номером диска и дорожки. Когда готовы 16 из 17, все 16 уже можно слушать.
5. **Добор пропусков.** Сохранить диск, номер и исходную ссылку каждой ожидающей позиции. При первой временной ошибке источника для этой позиции начать отсчёт 24 часов. В течение этого срока повторять попытки с увеличивающимися интервалами, затем перейти к ручному добору. Сохранить в SQLite срок окончания и время следующей попытки, чтобы перезапуск бота сохранял расписание. Для добора пользователь также может прислать точную ссылку либо файл.
   - В Puuk, пока у *MILITANTUM* загружается № 14, треки № 15–17 уже видны под своими номерами. Когда № 14 готов, он займёт место между № 13 и № 15.
   - При позднем доборе в Telegram бот сам отправляет найденный трек сразу после проверки. Файл приходит без звука уведомления, с названием альбома и исходной позицией в подписи, например «MILITANTUM · Трек 4 из 17». После подтверждения доставки убрать эту позицию из пропусков и обновить счётчик в исходном сообщении о загрузке.
6. В режиме «В Puuk» готовность означает, что запись существует в каталоге и файл доступен для воспроизведения. Передавать такие треки в существующую очередь анализа для «Волны». В режиме «В Telegram» отправлять по одному треку в сообщении. Первый трек отправить сразу после проверки его файла. Остальные отправлять по диску и номеру дорожки, а для плейлиста — по исходным позициям. Если № 3 готов раньше № 2, отправить его после доставки № 2 или после того, как № 2 отмечен пропущенным. Для FLAC использовать оригинальный файл как документ. В сообщении о загрузке перечислить пропуски по номерам. [Очередь анализа медиатеки](../../brain/services/embedding_queue_service.py)
7. Под итогом импорта **на сервер** показать «♡ В медиатеку» для альбома или обычного плейлиста, «♡ В избранное» для одиночного трека. Подборку самого Spotify завершить сводкой о треках в общем каталоге. После нажатия на сердце показать «♥ В медиатеке» или «♥ В избранном». Повторное получение нажатия приводит к тому же результату.

При приёмке добора через `/tg` пропустить № 4 и доставить остальные 16 треков. Смоделировать успешную повторную попытку на следующее утро в пределах 24 часов. Без действий пользователя в чате должно появиться одно новое вложение с подписью «MILITANTUM · Трек 4 из 17» и тихой отправкой. У прежнего сообщения о загрузке счётчик меняется с «16 из 17» на «17 из 17». После перезапуска проверить, что уже доставленные файлы не отправились повторно.

В отдельном прогоне оставить источник недоступным и перезапустить бота на 23-м часу. По истечении суток восстановить источник. Проверить, что автоматические запросы прекратились, в `/downloads` у № 4 видна причина пропуска, а нажатие «Повторить» доставляет только этот трек в рамках прежнего задания.

### Мои загрузки в Telegram

Команда `/downloads` в меню бота по запросу показывает одним сообщением незавершённые загрузки владельца. В каждой строке указать название, назначение, состояние и счётчик, например «Вслух · В Puuk · На паузе · 80 из 300». В список входят задания в очереди, в работе, на паузе и с пропусками для добора. Если список пуст, показать «Незавершённых загрузок нет». Длинный список листать кнопками в том же сообщении.

Пока в задании остаётся хотя бы один пропуск, сохранять его в `/downloads` независимо от давности импорта. При результате «298 из 300» веб-клиент и приложение iOS показывают в плейлисте только 298 готовых к воспроизведению позиций. Названия двух пропущенных песен, их исходные номера и причины пропуска видны в `/downloads`. Как только очередной файл проверен и опубликован в Puuk, песня появляется на своём месте в плейлисте. Задание уходит из списка незавершённых после добора последней позиции или явной отмены импорта владельцем.

Если пользователь слушает плейлист по порядку и № 4 догружается во время № 3, плеер сам вставляет её перед № 5. № 3 доигрывает до конца, затем звучат № 4 и № 5. Если к моменту публикации № 4 уже играет № 5, после неё звучит № 6. В обоих случаях № 4 сразу доступна для ручного выбора между № 3 и № 5 в плейлисте.

Если при публикации № 4 включено перемешивание, в плейлисте её сразу можно выбрать вручную. Плеер продолжает играть по уже составленной очереди. При следующем запуске плейлиста он учитывает и № 4. [Порядок воспроизведения в вебе и iOS](../design/DESIGN.md#порядок-воспроизведения--решение-от-2026-10-30)

Когда истекли 24 часа автоматических попыток, у каждой пропущенной позиции показать её номер, причину и кнопку «Повторить». Одно нажатие запускает одну попытку получить эту песню в том же задании. Если в плейлисте несколько пропусков, показать также «Повторить все 12» с актуальным числом позиций. Общая кнопка запускает по одной попытке для каждой позиции, которая ещё ждёт ручного повтора. Если нажать обе кнопки подряд, каждая позиция попадёт в очередь один раз.

После успешной попытки убрать песню из пропусков. После ошибки сразу показать её причину и снова включить «Повторить». Обновить счётчик и кнопки в той же карточке. Следующая попытка для этой позиции начнётся только по новому нажатию пользователя, в том числе после перезапуска бота.

У плейлиста на паузе показать «Продолжить» прямо в списке. Подробности задания, остальные доступные действия и возврат к списку открываются в том же ответе на `/downloads`. Перед каждым действием проверить владельца и текущее состояние задания по его ID. Если текущее сообщение о загрузке доступно, обновить и его. Если пользователь удалил его, управлять загрузкой по-прежнему можно через `/downloads`. ### Что создаёт ссылка на плейлист в режиме «В Puuk»

В сообщении о ходе импорта плейлиста показать владельцу «Пауза» и «Отменить импорт».

При создании личной копии сохранить в задании список позиций в порядке автора. После паузы продолжить по этому списку. Если на старте было 300 позиций, итоговый счётчик при полном импорте — «300 из 300». В следующий раз сравнить состав, когда после завершения задания владелец снова пришлёт ссылку в режиме «В Puuk». Тогда показать изменения и предложить обновить ту же копию.

- **«Пауза»** сразу останавливает все текущие загрузки этого плейлиста, даже если трек уже скачан на 90%. Закрыть соединения, освободить места в очереди и приостановить запуск следующих позиций. У каждого прерванного файла сохранить полученную часть, её фактический размер на диске и сведения о версии файла. В личной копии по-прежнему играют готовые треки. В сообщении показать, например, «На паузе · 80 из 300» и кнопки «Продолжить» и «Отменить импорт». Выбранная пользователем пауза действует и после перезапуска бота.
- **«Продолжить»** возобновляет то же задание и пропускает готовые позиции. Плейлист сохраняет свой ID. Для прерванного трека снова открыть ту же запись VK. Если для того же ресурса сохранён строгий `ETag`, запросить остаток с `If-Range`. Если заранее известна контрольная сумма SHA-256 полного оригинала, можно запросить остаток и сверить сумму после сборки. Ответ `206` дописывать с первого несохранённого байта после проверки `Content-Range` и полного размера. Полный ответ `200` записывать с нуля. Если подтвердить версию или диапазон не удалось либо итоговая сумма разошлась, заново получить только этот трек. Готовый файл проверить перед публикацией. [Условные запросы диапазона в HTTP](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.5)
- **«Отменить импорт»** завершает задание, в том числе поставленное на паузу. При первом импорте удалить приватную копию, созданную этим заданием. Уже опубликованные треки остаются в общем каталоге и доступны для «Волны». При отмене обновления ранее созданный плейлист остаётся у владельца. Повторное нажатие показывает итог «Импорт отменён». При публикации результата по отдельному треку сверять состояние задания.

| Чья подборка | Что появляется в Puuk | Что происходит при повторной отправке |
| --- | --- | --- |
| Плейлист пользователя, артиста или сообщества на поддерживаемой площадке, включая Spotify | Приватная копия с названием и порядком треков в аккаунте того, кто прислал ссылку. Видимость исходной подборки может быть любой доступной этому подключению. Сами подтверждённые записи доступны через общий музыкальный каталог | Найти копию по пользователю Puuk, площадке и ID плейлиста. Если импорт на паузе, продолжить его. Для уже завершённого импорта показать изменения и применить их к этой копии после подтверждения. У двух пользователей, приславших одну ссылку, свои копии |
| Подборка, созданная самим Spotify | Только отдельные треки в общем каталоге и штатный анализ для «Волны». В результате импорта количество новых плейлистов и автоматических лайков равно нулю | Добавить новые подтверждённые записи, переиспользовать уже доступные, повторить пропуски. Каждый такой импорт только пополняет каталог |

Для выбора поведения использовать площадку и подтверждённый идентификатор владельца из данных о плейлисте. Пользовательская подборка с названием «RapCaviar» остаётся обычным приватным импортом. Подлинный RapCaviar от Spotify использовать как контрольный пример второго случая. [Данные владельца в Spotify](https://developer.spotify.com/documentation/web-api/reference/get-playlist) · [RapCaviar в Spotify](https://open.spotify.com/embed/playlist/37i9dQZF1DX0XUsuxWHRQd)

При проверке приватности первый пользователь импортирует обычный плейлист и открывает его в Puuk. Второй находит ту же музыку в общем каталоге, а при открытии ссылки на чужую приватную копию получает сообщение об ограниченном доступе. Если второй сам импортирует исходную ссылку, у него появляется собственный плейлист с отдельным ID.

Для проверки обновления оба пользователя импортируют плейлист друга с одной песней «Thriller». Первый убирает её из своей копии и добавляет «Billie Jean». Друг добавляет в источник «Beat It», оба пользователя подтверждают обновление. У первого теперь «Billie Jean» и «Beat It», у второго — «Thriller» и «Beat It». «Thriller» по-прежнему доступен в общем каталоге и для «Волны».

Для проверки перестановки взять плейлист «Thriller», «Bad», «Beat It». В своей копии владелец ставит «Beat It» первой и сразу за ней добавляет «Human Nature». Друг меняет порядок исходного плейлиста на «Bad», «Billie Jean», «Beat It», «Thriller». Ещё до подтверждения бот показывает, что «Beat It» перейдёт с 1-го места на 3-е, а «Human Nature» — со 2-го на 4-е. При отмене в копии остаются четыре песни с «Beat It» и «Human Nature» в начале. Повторная отправка ссылки снова показывает изменения. После нажатия «Обновить» ожидаемый порядок — «Bad», «Billie Jean», «Beat It», «Human Nature», «Thriller». Так же проверить подтверждение, когда автор только переставил песни.

Для проверки удаления начать с личной копии «Thriller» → «Beat It» → «Human Nature» → «Bad», в которую владелец сам добавил «Human Nature». Автор убирает «Beat It». При повторном импорте бот показывает будущий порядок «Thriller» → «Human Nature» → «Bad». Нажатие «Обновить» сохраняет эти три позиции, а «Отмена» оставляет все четыре в исходном порядке.

Для проверки повторов импортировать плейлист, где одна запись «Billie Jean» стоит под № 3 и № 12. Обе позиции должны использовать один файл. В вебе и iOS при воспроизведении по порядку песня должна прозвучать дважды. Отдельно запустить № 12 и нажать «Дальше». Должна заиграть № 13. При повторной отправке той же ссылки в списке остаются два появления песни. Затем удалить из личной копии № 12. После того как автор добавит песню в конец и владелец подтвердит обновление, «Billie Jean» должна остаться только на 3-м месте, а в конце должна появиться новая песня.

Проверить также закрытую ссылку Spotify и ссылку, по которой источник вернул только название и обложку. В обоих случаях показать «По этой ссылке мне недоступен список треков. Можно прислать ссылки на отдельные треки». У такого задания ноль созданных плейлистов. При повторном импорте недоступный список также не служит основанием очистить уже сохранённую копию.

### Повторная проверка из плеера

Услышав другую версию, пользователь открывает «⋯» у трека в Puuk и нажимает «Не та версия». В вебе и iOS действие отправляет на проверку ID выбранного трека и версию его аудиофайла. Когда сервер принимает задание, в плеере появляется «Трек отправлен на проверку». Пока проверка идёт, повторное нажатие показывает её статус. [Меню в вебе](../../app/web/src/components/player/DockActionsMenu.tsx) · [Меню в плеере iOS](../../app/ios/puuk-ios/components/fullplayer/PlayerHeader.js)

Бот сверяет отмеченный файл с запрошенной записью. Если подтвердится подмена, применяются общие правила ниже для воспроизведения, «Волны» и добора оригинала. При приёмке нажать «Не та версия» у «танцуй» и перейти к следующей песне. Проверка должна завершиться для выбранного файла «танцуй». Если другой импорт уже заменил этот файл оригиналом, в каталоге остаётся доступен оригинал.

### Когда пользователь прислал ссылку ещё раз

- **Плейлист на паузе.** Если владелец новым сообщением снова прислал ссылку на тот же плейлист в режиме «В Puuk», сразу выполнить «Продолжить» для этого задания. При «80 из 300» продолжить с № 81 в той же личной копии. В текущем сообщении о загрузке показать «Загружаю · 80 из 300» и кнопку «Пауза».
- **Сообщение о загрузке удалено.** При возобновлении по повторной ссылке отправить одно новое сообщение с текущим счётчиком, например «Продолжаю · 80 из 300», и кнопкой «Пауза». Сохранить его ID в том же задании. В этом сообщении обновлять прогресс и показать итог, в том числе после перезапуска бота.
- **Альбом.** При повторном импорте того же издания заново прочитать состав, номера, исполнителей, обложку и теги. Для каждой позиции проверить звук. Обновить сведения в каталоге под прежним ID трека, сохраняя лайки, историю и позиции в плейлистах. Если нужна замена аудио, опубликовать проверенный файл вместе с его данными, обновить версию файла для клиентов и передать запись на анализ. Ремастер или другое издание с собственным идентификатором обрабатывать как отдельный релиз.
- **Свой FLAC и найденный MP3.** При обновлении издания с подбором звука, например по ссылке Spotify, оставить подтверждённый пользовательский FLAC файлом для воспроизведения, если нашёлся только MP3 той же записи. Обновить сведения о релизе по обычным правилам. Формат, размер, битрейт и происхождение в Puuk должны описывать сохранённый FLAC. При прямом импорте конкретной загрузки из VK сохранить связь этой позиции с файлом VK. Если он отличается от личного FLAC, оба файла сохраняют собственное происхождение.
- **Подмена обнаружена до получения оригинала.** Если под № 13 подтверждён концерт, прекратить выдачу этого файла под именем альбомного трека, в том числе из «Избранного» и плейлистов. Сразу исключить эту позицию из подбора «Волны». Связи пользователя с треком сохранить. При синхронизации клиент применяет тот же статус к своей кэшированной копии. В отчёте показать № 13 и «Прислать файл или ссылку». После получения оригинала восстановить воспроизведение под прежним ID и отправить файл на анализ. Временная ошибка запроса к источнику переводит задание в ожидание повтора. Для отключения воспроизведения требуется установленное расхождение версий.
- **Альбом из старого бота.** Если в каталоге ещё нет связи с исходной ссылкой, найти прежнюю карточку по исполнителю альбома, изданию, составу и позициям. При единственном подтверждённом совпадении связать ссылку с существующей карточкой и обновить её. Если подходят два издания, показать их названия и годы для выбора. Проверить этот путь на старой карточке с неверно подобранной записью.
- **Приватная копия плейлиста.** Сравнить новый порядок источника с порядком при последнем подтверждённом импорте. Для каждой копии хранить ручные добавления и удаления по отдельным вхождениям трека. Удаление одного повтора касается только выбранного вхождения. При обновлении сопоставить его с позицией источника по устойчивому идентификатору, если площадка его даёт. В остальных случаях использовать предыдущий состав и соседние треки. Если две позиции всё ещё неразличимы и от выбора зависит личная правка, показать их рядом с соседними треками при подтверждении обновления. Владелец может вернуть удалённую позицию ручным добавлением. Пропуск из-за недоступного аудио остаётся в отчёте для добора.
- **Место личной песни.** Сохранить, после какого вхождения в своей копии владелец поставил песню. При перестановке источника поместить её сразу за этим вхождением. Несколько личных песен, поставленных подряд, сохраняют свой порядок. Если в списке две строки «Beat It» и владелец вставил «Human Nature» после второй, проверить, что «Human Nature» следует за выбранной строкой и после того, как та окажется выше другой строки «Beat It». Если выбранное вхождение исчезло, найти ближайшие сохранившиеся вхождения до и после личной песни по прежнему порядку копии. Когда они по-прежнему идут в том же порядке, оставить песню между ними. Показать её место в общем подтверждении обновления.
- **Что увидит владелец.** Сразу показать список песен, которых коснётся обновление. Для новой песни указать, где она появится, для удаляемой — с какого места уйдёт, для переставленной — откуда и куда переместится. Например, «Billie Jean появится на 2-м месте», «Beat It перейдёт с 1-го места на 3-е». Отдельно указать, какие личные добавления и удаления сохранятся. Если список длинный, сразу открыть первую страницу с названиями. Остальные страницы листать в том же сообщении.
- **Подтверждение обновления.** Кнопки «Обновить» и «Отмена» доступны на каждой странице. Одно нажатие «Обновить» применяет весь показанный список, в том числе когда автор только переставил песни. При отмене сохраняется текущий плейлист. При отсутствии изменений в источнике с последнего принятого обновления сообщить «Плейлист уже актуален». Если за время просмотра изменился источник или сама копия, пересчитать результат и запросить подтверждение изменившегося списка.
- **Повтор доставки Telegram.** Повторную доставку уже обработанного сообщения распознавать по ID чата и сообщения. Вернуть текущее состояние связанного задания. Для задания на паузе это «На паузе» с прежним счётчиком.

Для хранения личного выбора учесть устройство текущего Brain. Избранные треки уже привязаны к пользователю, альбомы выдаются из общего каталога. Для альбомов предусмотреть связь пользователя с сохранённым альбомом и отображение в клиентах. Для обычной подборки использовать штатный приватный плейлист с владельцем из привязанного аккаунта Puuk и связью с исходной подборкой. [Схема медиатеки](../../brain/repositories/schema.py) · [Альбомы](../../brain/routers/albums.py) · [Плейлисты](../../brain/routers/playlists.py)

## Файлы, папки и метаданные

- **Один файл.** Принимать аудио из плеера Telegram и аудиофайл, присланный документом. Определить формат по содержимому, проверить чтение аудио, извлечь теги, обложку и технические свойства. Для публикации в Puuk сохранить исходные байты. Проверять повторную отправку одного файла по содержимому.
- **Файл без тегов.** Для одиночного файла вроде `07 Human Nature.flac` без сведений об издании найти возможный релиз и до сохранения показать название, исполнителя и альбом. Применять выбранные данные после подтверждения. Если поиск не дал подходящего релиза, предложить указать его файлом CUE или ссылкой.
- **Папка альбома.** Для готовой папки рекомендуем ZIP верхнего каталога, отправленный документом. Для FLAC, MP3 и M4A достаточно режима «Без сжатия». Он быстро упаковывает уже сжатое аудио и сохраняет папки дисков, CUE и обложку. Бот принимает также обычный ZIP со сжатием. У всей папки *Thriller 40* объём около 718 МБ, из них около 629 МБ — аудио. Из одного вложения получится один альбом на 19 дорожек. Для нескольких файлов с телефона оставить прямую отправку аудио или документов. Если пользователь объединяет несколько сообщений в альбом, кнопка «Готово» завершает сбор. Перед публикацией показать распознанное издание, диски, число дорожек и спорные значения.
- **Крупные файлы.** Облачный метод Telegram `getFile` ограничивает скачивание ботом до 20 МБ. Все 19 FLAC из примера превышают этот предел. Для прямого приёма таких вложений планируем локальный Telegram Bot API на сервере Puuk. Предусмотреть временный диск под входной архив, распакованное содержимое и рабочие файлы, безопасную распаковку и очистку после завершения. Проверить на реальном FLAC и на полной папке. [Telegram Bot API](https://core.telegram.org/bots/api#using-a-local-bot-api-server) · [Ограничения облачного метода](https://core.telegram.org/bots/api#file)
- **Поля Puuk.** Использовать штатное чтение метаданных Brain. Заполнять название трека, исполнителей трека и альбома в исходном порядке, альбом, год, жанр, номер диска и дорожки, позицию в альбоме, комментарий, текст песни и обложку. Из самого файла брать длительность, формат, размер, битрейт, частоту дискретизации и число каналов. Заполнять доступные значения, сохраняя исходные байты аудио. Идентификаторы сторонних каталогов и доказательства совпадения относятся к истории импорта. Жанры, полученные моделью, и громкость рассчитывает штатный анализ Puuk. [Чтение тегов](../../brain/metadata.py) · [Поля каталога](../../brain/serializers.py)
- **Порядок и обложка.** В первую очередь читать структурированные теги. Использовать CUE, M3U и структуру каталогов для проверки порядка и восполнения пробелов. У проверенного *Thriller 40* файл `scanBox/main.jpg` показывает лицевую сторону издания, а `folder.jpg` у CD2 — поверхность второго диска. На карточке обоих дисков ожидаем лицевую обложку издания. При неоднозначной сборке дать один выбор на весь альбом.
- **Материалы издания.** Изображения из папки могут служить источником обложки. CUE и M3U помогают восстановить номера и порядок дорожек. Страницы буклета, изображения поверхности CD, журналы копирования диска и замеры динамического диапазона относятся к сопроводительным материалам оригинального комплекта. Для импорта достаточно заполнить существующие поля Puuk.
- **Файл для пропуска.** При ответе на конкретную позицию привязать файл к её номеру и изданию, прочитать его собственные теги. Если длительность или исполнитель явно расходятся, показать это пользователю до сохранения его выбора.
- **Дополнение тегов.** После подтверждения издания заполнить пустые поля Puuk, в том числе исполнителя альбома, жанр и текст песни, когда есть проверяемые данные для конкретной записи. Применять это к записям каталога Puuk, сохраняя байты присланного файла. Если источники предлагают разные значения уже заполненного поля, показать текущее и предлагаемое значения одним списком на весь импорт. Пустой ответ источника оставляет поле доступным для будущего дополнения.

### Приёмка на плейлисте VK из 300 позиций

Пользователь ожидает плейлисты на несколько сотен треков. Для проверки берём 300 позиций, включая два появления одной и той же записи. Этот размер — ориентир для испытания.

1. Отправить одну ссылку в режиме «В Puuk» и зафиксировать все 300 позиций в порядке VK. Сохранять в задании состояние каждого вхождения и контрольную сумму его готового файла.
2. В тестовом окружении прервать обработчик, когда опубликовано 150 позиций, а очередной файл получен лишь частично. После перезапуска бот сам продолжает то же задание. У готовых позиций проверить доступность в Puuk и отсутствие повторного скачивания. Частично полученный файл становится доступен для прослушивания после полной загрузки и проверки.
3. Если VK отдаёт все исходные записи, в финале в приватной копии воспроизводятся 300 из 300 позиций. Сверить их порядок с исходным списком. Обе позиции с повторяющейся песней проигрываются на своих местах и используют один файл. Записать время до первого доступного трека, общее время и пиковый объём временных файлов.
4. В отдельном прогоне задать ошибку получения для одной записи, которая встречается в списке один раз. Ожидаемый результат — «299 из 300» с номером и причиной пропуска. Когда тот же файл снова станет доступен в VK, добрать только эту позицию в существующую копию.
   - Для проверки ручного повтора оставить 12 разных записей недоступными на сутки. При «288 из 300» открыть `/downloads` и проверить, что видна кнопка «Повторить все 12». Восстановить доступ к десяти записям, оставив недоступными исходные № 4 и № 14. У № 4 нажать «Повторить» и, пока она ждёт ответа, дважды нажать общую кнопку. Проверить по одной ручной попытке на каждую из 12 позиций и ноль запросов к 288 готовым. В прежней карточке ожидаются «298 из 300», причины двух пропусков, «Повторить» у каждой песни и «Повторить все 2».
   - Перезапустить бота, восстановить доступ к двум записям и перевести тестовые часы на неделю вперёд. В `/downloads` по-прежнему видны «298 из 300», названия обеих песен и кнопки повтора. До нового нажатия число попыток остаётся прежним. В обоих клиентах проверить, что в плейлисте ровно 298 строк, № 3 соседствует с № 5, а № 13 — с № 15.
   - Нажать «Повторить все 2» и проверить, что загружены только эти файлы. Сначала опубликовать № 14. В обоих клиентах теперь 299 строк, № 14 стоит между № 13 и № 15.
   - В вебе и iOS запустить плейлист по порядку с № 3. Убедиться, что следующей стоит № 5, и во время воспроизведения № 3 опубликовать № 4. Проверить, что № 3 доигрывает без перезапуска и оба плеера сами последовательно воспроизводят № 4 и № 5 по одному разу. В плейлисте под прежним ID все 300 позиций в исходном порядке. После «300 из 300» в сообщении бота задание исчезает из списка незавершённых.
   - В отдельном прогоне в вебе и iOS опубликовать пропущенную № 4 после перехода с № 3 на № 5. Проверить, что № 5 доигрывает и автоматически начинается № 6. Затем открыть плейлист, выбрать № 4 между № 3 и № 5 и проверить, что воспроизводится именно она.
   - Оставить пропуск только у № 4. В вебе и iOS запустить плейлист с перемешиванием и в каждом клиенте записать последовательность оставшихся позиций. Пока звучит первый трек, опубликовать № 4 и сверить всю оставшуюся очередь с записанной. Проверить, что № 4 уже можно включить из плейлиста вручную. Заново запустить плейлист с перемешиванием и проверить, что среди текущей и предстоящих позиций № 4 встречается ровно один раз.
5. Для проверки приоритета разрешить одну одновременную загрузку. Пока скачивается позиция № 151, тот же пользователь отправляет команду `/tg` со ссылкой на песню вне плейлиста. После завершения № 151 первой загружается отдельная песня, затем бот сам берёт № 152. Песня приходит в чат до окончания импорта. В приватной копии Puuk остаются все 300 позиций в порядке VK.
6. В прогоне с одной одновременной загрузкой нажать «Пауза», когда уже играют 80 треков, а файл № 81 получен на 90%. Проверить, что передача № 81 остановилась, освободившееся место доступно другой загрузке, № 82 ожидает, а в плейлисте по-прежнему играют 80 треков. Перезапустить бота, проверить состояние «На паузе» и нажать «Продолжить». Проверить следующие ответы источника по № 81.
   - Для подтверждённой версии и верного диапазона получить только последние 10%.
   - Полный ответ (`200`) записать с нуля, в том числе при смене версии файла. Если у исходной загрузки отсутствуют и строгий `ETag`, и эталонная сумма, сразу запросить файл целиком.
   - Если начало диапазона неверно или SHA-256 после сборки разошлась с эталоном, получить № 81 целиком. До проверки дорожка остаётся недоступной в плейлисте.
   - В каждом прогоне сверить SHA-256 готового № 81 с соответствующим полным оригиналом. Проверить, что ID плейлиста прежний, а повторных запросов к готовым 80 трекам было ноль.
7. Начать импорт нового плейлиста и отменить его после 80 готовых позиций. Проверить отмену во время работы и в отдельном прогоне после паузы. Личная копия удалена, опубликованные треки воспроизводятся из общего каталога. Проверить, что и после запоздалого ответа по начатой загрузке, и после перезапуска задание остаётся отменённым, а число созданных им плейлистов в аккаунте равно нулю.
8. После паузы на «80 из 300» перезапустить бота и открыть `/downloads` из двух аккаунтов. Продолжить плейлист из списка владельца. Проверить, что второй пользователь видит только свои задания, два нажатия «Продолжить» запускают одну обработку, а счётчик и итог «300 из 300» появляются под исходным ID сообщения. Отдельно удалить исходное сообщение, пока импорт на паузе, и возобновить его из списка под прежними ID задания и плейлиста.
9. После паузы на «80 из 300» и перезапуска повторно доставить исходное сообщение пользователя с тем же ID. Убедиться, что задание по-прежнему на паузе. Затем от имени владельца отправить ту же ссылку новым сообщением в режиме «В Puuk» и повторить доставку этого нового сообщения. В нём статус меняется на «Загружаю · 80 из 300», затем растёт счётчик.
   - В отдельном прогоне на паузе удалить сообщение бота с прогрессом и снова прислать ссылку в режиме «В Puuk». Ожидается одно новое сообщение «Продолжаю · 80 из 300» с кнопкой «Пауза». Записать его ID, перезапустить бота и повторить доставку уже обработанного сообщения пользователя. Проверить, что прогресс и итог «300 из 300» появляются под записанным ID, задание и плейлист сохранили свои ID, а за всё возобновление бот отправил ровно одно новое сообщение.
   - Пока импорт на паузе, добавить в конец исходного плейлиста пять песен. Возобновить импорт ссылкой и проверить, что в копии появились исходные 300 позиций в прежнем порядке. Итог в чате — «300 из 300». По запросам к источнику проверить, что бот не искал изменения состава при возобновлении и завершении. После завершения прислать ссылку новым сообщением. Теперь бот показывает пять добавлений. До нажатия «Обновить» в копии 300 позиций, после подтверждения и загрузки — 305 под прежним ID плейлиста.
   - Для длинного списка изменить несколько десятков позиций в источнике и снова прислать ссылку после завершённого импорта. Проверить, что первый ответ уже содержит названия песен и их позиции. ## Как принимаем импорт MILITANTUM

1. Подключить нового бота к тестовому каталогу, в котором ещё нет этого альбома. Один раз отправить ссылку Spotify в режиме «В Puuk». В том же задании бот самостоятельно перебирает источники для спорных позиций.

Сверить звук каждой дорожки с фрагментом соответствующего трека Spotify при исходной скорости. Для № 13 и № 14 дополнительно сверить полные дорожки с публикациями TRV.
