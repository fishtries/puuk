# План: проверенная пословная разметка в iOS

Статус: локальная реализация исправлена после ревью (2026-11-10). Выпуск и приёмка на iPhone не выполнены. Проверки и команды: [WORD_LYRICS.md](../WORD_LYRICS.md).

Цель: открыть Psychoboost в существующем экране текстов iOS и увидеть подсветку слов по проверенным таймингам. Затем подключить Stateside и Without Me. Приоритет — точность и сохранение ручной работы.

## 1. Что уже решено и что входит в первый выпуск

- Выбор пользователя: Stateside — MMS на оригинале; Without Me — MMS на оригинале; Psychoboost — Whisper `stable-retry` на оригинале, с повторной обработкой сбойных строк и ручными правками. Не подменять этот выбор `stable-guarded` или другим кандидатом.
- Все вычисления моделей остаются вне iOS. Сервер отдаёт готовые данные, телефон отображает их по времени аудиодвижка.
- Интегрируемся в существующий экран текстов. Сохраняем его скролл, переходы, тап по строке и построчный LRC для песен без словесных таймингов.
- В первом выпуске подсвечиваем слово целиком во время его интервала. Плавная заливка внутри слова — отдельный следующий этап: длительность слова не даёт достоверных таймингов букв.
- Публикуем только явно выбранный снимок результата. Наличие ручных правок не означает, что весь трек прослушан и проверен.
- Не включаем автоматическую обработку библиотеки, редактор на телефоне, новые модели, GPU-зависимости в backend, массовую замену текстов или изменения веб-плеера.
- В AGENTS.md записано, что прежний word-level пайплайн удалён. Новая задача разрешает добавить отображение проверенных данных; она не требует восстанавливать удалённые очереди и старую схему. Уточнить эту формулировку в документации при реализации.

## 3. Контракт данных — зафиксировать до параллельной реализации

Расширить существующий ответ `/lyrics` одним необязательным полем `wordLyrics`. Существующие поля, их смысл и авторизацию сохранить. Отсутствующие или неактуальные тайминги: `wordLyrics: null`. Старые клиенты игнорируют новое поле; новые работают со старым сервером без него.

Предлагаемый контракт v1, пример с искусственным текстом:

```json
{
  "wordLyrics": {
    "schemaVersion": 1,
    "revision": "sha256-of-canonical-content",
    "trackId": "opaque-track-id",
    "audioSha256": "sha256-of-imported-audio-file",
    "durationMs": 180000,
    "lines": [
      {
        "id": "line-0001",
        "text": "Example phrase!",
        "startMs": 1000,
        "endMs": 2600,
        "words": [
          { "id": "word-0001", "from": 0, "to": 7, "startMs": 1000, "endMs": 1500 },
          { "id": "word-0002", "from": 8, "to": 15, "startMs": 1700, "endMs": 2600 }
        ]
      }
    ]
  }
}
```

Правила контракта:

1. Время — целые миллисекунды от начала исходного аудио. Перевод секунд выполняется один раз при экспорте с округлением. UI переводит единицы на границе с аудиоплеером. Интервалы полуоткрытые `[startMs, endMs)`.
2. `text` хранится дословно, включая пробелы и пунктуацию. `from/to` — полуоткрытые индексы Unicode code points в тексте строки, а не UTF-16 code units. В JS использовать заранее вычисленный `Array.from(text)`; покрыть emoji/не-BMP тестом. Не нормализовать текст для отображения.
3. Идентификаторы обозначают конкретное вхождение слова. Повторяющиеся `part of me` остаются отдельными элементами. Запрещено сопоставление по уникальному тексту слова или удаление дублей.
4. Каждое слово: `0 <= startMs < endMs <= durationMs`, конечные целые числа, корректный непустой диапазон символов. Диапазоны символов не перекрываются. Порядок слов сохраняется.
5. Слова идут в порядке текста; начала интервалов могут убывать, если так задано в источнике. Перекрытия допустимы: одновременно подсвечиваются все активные слова. Не обрезать и не сдвигать их автоматически ради красивой схемы. Подозрительные интервалы выводить в отчёте импорта.
6. Для строки со словами границы равны минимальному началу и максимальному концу её слов. Если хотя бы у одного слова нет корректных таймингов, импортировать строку целиком как `words: []` с исходными LRC-границами и вывести предупреждение. Нулевые слова не выдавать за проверенные. Если корректных LRC-границ тоже нет — остановить публикацию этого снимка с диагностикой строки.
7. Строки следуют в порядке исходного текста; начала могут убывать. Для построчной строки конец берётся из следующего строго более позднего LRC-якоря либо длительности аудио. Перекрытия строк не перестраивают порядок текста.
8. При наличии wordLyrics экран использует его строки целиком, включая строки с `words: []`. Не накладывать слова на независимо перепарсенный LRC по индексам: тексты и группировка могут различаться. При отсутствии/невалидности объекта целиком использовать существующий LRC/plain сценарий.
9. `revision` — хеш канонического содержимого снимка без самого поля revision. Одинаковый снимок даёт одинаковую ревизию; повторный импорт идемпотентен. Утвердить канонизацию в Python-экспортёре, клиент хеш не пересчитывает.
10. Происхождение модели, checksum входного экспорта, ручные/принятые изменения, время импорта и частичность проверки хранятся на сервере в provenance. Названия моделей не выводятся в обычный экран плеера.

Перед написанием кода агент контракта проверяет схему на реальном экспорте. Если требуются изменения, сначала обновляет этот раздел и общую тестовую фикстуру, затем передаёт их backend/iOS. Не создавать по отдельной версии контракта в каждом агенте.

## 4. Порядок работ и границы агентов

Работы ниже — задания для последующего запуска агентов. Сам план не запускает их и не выполняет деплой.

Зависимости: A → B и C; B+C → D; D → E. После заморозки контракта B и C могут работать параллельно в непересекающихся файлах. Координатор разрешает изменения общих файлов. Изменения AppleLyricsView и контроллера принадлежат одному iOS-агенту.

### Агент A — снимок данных, экспорт и контракт

**Результат:** воспроизводимый экспорт Psychoboost, валидатор, искусственная общая фикстура контракта, отчёт о происхождении и качестве.

1. Прочитать LOCAL_EDITOR.md, selected-models.json, обработчик `downloadResult` и структуру исходных слов. Не запускать новое выравнивание и не менять выбранные модели.
2. Получить актуальный полный экспорт из текущего редактора. Последние ручные правки могут находиться только в localStorage браузера. Не использовать чистый тестовый профиль как источник пользовательского результата. Не очищать/перезаписывать хранилище пользователя. Если актуального экспорта нет и получить его инструментами нельзя, запросить именно полный экспорт; независимо продолжить реализацию на фикстуре, но не публиковать исторические данные как последние.
3. Сохранить входной JSON неизменным с checksum. Текущий экспорт помечен `draft_with_protected_manual_edits`: не преобразовывать это автоматически в «весь трек проверен».
4. Сопоставить экспериментальный slug с реальным track_id сервера по манифесту, исходному пути и аудиофайлу. Название/исполнитель сами по себе недостаточны. Сверить длительность и SHA-256 точной копии аудио; не угадывать соответствие.
5. Реализовать отдельный CLI преобразования, например `scripts/lyrics/export_word_lyrics.py`, и валидатор в backend-модуле, пригодном также для импорта. CLI принимает пути явно, не зависит от `/home/fish` и содержимого браузера.
6. Перенести слова и границы без повторного токенизатора, который меняет пунктуацию. Сопоставить ID и диапазоны текста; неоднозначность — ошибка с ID строки, а не автоматическая подстановка.
7. Вывести отчёт: число строк/слов, ручных правок (если доступно), строк с fallback, некорректных границ, перекрытий и подозрительно долгих слов. Длительное слово само по себе не исправлять.
8. Подготовить небольшую синтетическую фикстуру с повторами, пунктуацией, пробелами, Unicode и строкой без словесных таймингов для Python/Jest. Не коммитить аудио, модели и полные реальные тексты в репозиторий.

**Приёмка:** повторный экспорт даёт тот же документ/revision; текст и количество вхождений не меняются; непринятых кандидатов нет; тайминги ручных правок совпадают с актуальным экспортом с допуском округления 0.5 ms. При недоступном актуальном экспорте результат явно отмечен как подготовка, а публикация остаётся незавершённой.

### Агент B — хранение, импорт и API

**Владение:** `brain/`, CLI импорта в `scripts/lyrics/`. Не менять экран iOS.

1. Добавить новую таблицу, например `track_word_lyrics`, отдельную от `tracks.lyrics`: track_id как уникальный ключ, schema_version, revision, payload_json, provenance_json, audio_sha256, подпись файла для обнаружения изменений, imported_at. Использовать актуальный следующий номер миграции; не предполагать, что 014 свободен к началу работы. Покрыть создание новой БД и обновление существующей.
2. Предоставить небольшие операции репозитория: получить действующий снимок, атомарно заменить валидированным снимком, удалить/отключить снимок конкретного track_id. Согласовать с существующим фасадом db. Не вводить универсальную инфраструктуру заданий.
3. Реализовать CLI импорта с dry-run по умолчанию и явным `--apply`; это интерфейс инструмента, а не требование повторно спрашивать пользователя на каждом локальном тесте. Импорт проверяет трек, документ и соответствие аудио; вся запись транзакционная. Повтор той же ревизии — no-op. Ошибка оставляет прежний документ целым. Перед заменой выдаёт резервный экспорт предыдущего снимка.
4. Хешировать аудио при импорте, не при каждом GET. Привязать запись к доступной идентичности файла (путь, размер, mtime_ns либо существующий надёжный механизм версии аудио). При обнаруженном изменении файла сканером или при проверке подписи на чтении перестать отдавать тайминги до повторной сверки. Записать предел: stat-подпись не обнаруживает подмену с тем же размером и временем; не выдавать её за криптографическую гарантию. Не добавлять полное хеширование библиотеки в запрос.
5. В `get_track_lyrics_payload` присоединять wordLyrics ко всем веткам ответа, включая отсутствие обычного текста и force-refresh. Валидный снимок должен отображаться даже при пустом LRC. Внешний поиск lyrics не должен заменять проверенный снимок и по возможности не нужен при наличии такого снимка. Проверить текущие ранние return до реализации.
6. Смена обычного текста/LRCLIB не должна склеивать его с существующим снимком. Самостоятельный снимок содержит собственный текст; правила его замены — только явный импорт. Смена самого аудио инвалидирует его.
7. Сохранить текущую авторизацию `/lyrics`; не создавать публичный endpoint загрузки файлов. Операции записи в первом выпуске выполняются CLI на сервере в существующем окружении.
8. Не включать payload в каталог/списки треков, не менять ETag каталога ради таймингов. Если ответ `/lyrics` кешируется, учесть revision и проверить обновление после импорта. Не строить новую систему кеширования без необходимости.
9. Ошибка/неподдерживаемая схема снимка даёт `wordLyrics: null` и диагностируемую серверную запись, а не падение всего endpoint. Отсутствие снимка — обычный случай, без error-логов на каждый запрос.

**Обязательные тесты:** все с временной `PUUK_DB_PATH`; импорт валиден/невалиден/повторен; атомарность замены; отсутствие трека; несовпадение аудио; устаревшая подпись; пустой LRC с валидным снимком; обычный LRC без снимка; старые поля ответа; защищённость endpoint; каталог не содержит payload и не получает лишнюю инвалидацию. Запретить реальную сеть в тестах внешних поставщиков.

**Приёмка:** локальный сервер отдаёт согласованную фикстуру новым клиентам, старые тесты API проходят, импорт не изменяет аудиофайлы или LRC.

### Агент C — iOS: данные и подсветка

**Владение:** iOS-файлы; если нужен новый модуль, разместить его рядом с существующими lyrics-компонентами. Не перерабатывать весь FullPlayerModal/usePlayerController.

1. Добавить разбор wordLyrics с проверкой версии, track_id, границ и структуры. Парсить один раз при получении ответа. При невалидном объекте использовать существующий LRC/plain путь. Подготовить единое представление строки для экрана, не дублировать всю логику скролла для нового формата.
2. В эффекте загрузки AppleLyricsView проверять HTTP status и игнорировать устаревшие ответы после смены track_id/unmount. Быстрая смена A→B→A не должна позволить старому запросу A перезаписать новый. На смене трека сразу сбрасывать старую подсветку. При ошибке запроса сохранять доступный fallback текущего трека, не показывать текст предыдущего.
3. Сохранить текстовый layout: слова размечаются внутри обычной строки, пробелы и пунктуация остаются на месте, переносы естественные. Не раскладывать слова произвольными независимыми кнопками. Выбор React Native-представления проверить на длинной строке и увеличенном шрифте.
4. Для v1 подсвечивать слово целиком в его интервале. Предстоящее слово — приглушённое; активное — контрастное; произнесённое — читаемое без активного акцента. Подсветка не меняет размер/жирность так, чтобы прыгала геометрия строки. В паузе сохранять состояние на текущей позиции. В промежутке между словами активного слова нет.
5. При пересечении интервалов подсвечивать все активные слова. Для выбора строки автоскролла использовать последнюю начавшуюся строку по времени, при равном начале — последнюю по исходному порядку. До первого начала активной строки нет. В инструментальной паузе допускается сохранять фокус на предыдущей строке, но не её активное слово. Строка с words: [] использует существующее построчное выделение.
6. Использовать существующее время аудио. Сначала измерить частоту и задержку status.currentTime на устройстве: короткие слова могут исчезать между редкими обновлениями. Если нужен интерполированный визуальный clock, синхронизировать его с последним status, playbackRate, playing и buffering. Останавливать на паузе/буферизации/уходе экрана; сбрасывать после seek, смены трека и возврата из background; ограничить экстраполяцию при устаревшем status. Не заводить независимый setInterval, считающий секунды песни.
7. Для визуального clock использовать shared values/worklets установленной Reanimated, если они нужны. Не перерисовывать весь список через React state на каждом кадре. Не менять глобальную частоту событий аудио без измерения последствий. Не добавлять постоянную поправку на слух.
8. Сохранить тап по строке: seek на startMs строки с переводом в секунды. Не добавлять отдельные тапы по словам. После подтверждённого seek состояние соответствует новой позиции; прежняя анимация не продолжает вести время вперёд.

## 6. Общий критерий завершения

Пользователь открывает Psychoboost, Stateside и Without Me в iOS и видит соответствующую выбранной модели разметку с сохранёнными актуальными правками.
