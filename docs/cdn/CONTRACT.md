## 1. Trust boundaries and verified evidence

Permanent HTTPS links identify catalog entities. They contain no playback permission. Catalog use and permission issuance require a Puuk session. A CDN URL is a bearer capability for one exact versioned audio object until expiry, without IP binding. Someone who copies it can use it until expiry. Logout, deletion and purge cannot erase downloaded bytes or reliably terminate an already open transfer.

The evidence boundary is:

| Evidence | Established | Not established |
|---|---|---|
| [S0](S0_BASELINE.md) and corrected [J1](J1_PROVIDER_AUDIT.md) | HTTPS/DNS respond; media currently proxies SPA/API; bounded Range/416 on 709-byte HTML; no AASA/Associated Domains/team/device acceptance | Audio cache HIT, token enforcement, audio Range, current authenticated CDN settings, geographic improvement |

## 2. Playback API, configuration and compatibility

### 2.1 Request and response

Keep authenticated `POST /api/media-ticket`, JSON body:

```ts
type MediaTicketRequest = {
  track_id: string;             // canonical lowercase UUID, existing v4/v5 accepted
  delivery?: 'direct' | 'cdn';  // absent means legacy direct, never CDN
};
type MediaTicketResponseV1 = {
  url: string;
  expires_in: number;           // integer seconds from server_time to expires_at
  expires_at: number;           // integer Unix seconds
  delivery: 'direct' | 'cdn';  // actual selection, not requested selection
  server_time: number;          // integer Unix seconds at issuance
  content_version: string | null; // sha256 hex when verified; null => direct only
  content_length: number | null;  // exact whole-file bytes of verified version, <= 500 MiB for cache
  download_binding: 'if-match' | 'immutable-path' | null;
  delivery_epoch: string;       // operator-controlled nonsecret release identifier
  cache_for: number;            // max permission reuse, 30 seconds in v1
};
```

The first three response fields retain their existing types and meaning. New clients send `delivery:'cdn'` only with their local CDN switch on; `direct` explicitly requests fallback. Unknown delivery values return 422. Unknown extra fields retain baseline Pydantic ignore behavior for compatibility. Normalize a parseable request UUID to canonical form before lookup/signing; malformed ID returns 400. Response URL paths themselves are strictly canonical (§4).

For every selection: validate the session and user, tombstone/access state, track, regular file, safe resolved path and availability **before** returning a URL. The current application gives authenticated users access to the shared catalog; do not invent per-track ACLs, and do not bypass any future access decision with fallback. Missing/deleted/unplayable objects return 404. A media JWT must not authenticate the ticket/share/catalog APIs: `get_current_user` must reject `scope:'media'`, while access JWTs without that scope remain compatible. This closes cross-use of a media ticket as an account credential.

Direct returns `/api/stream/<id>?mt=<existing-track-bound-media-JWT>`, TTL `MEDIA_TICKET_TTL_SECONDS=600` by default, new-server validated range 60–1800. Preserve old Bearer direct GET and media-ticket GET; add explicit HEAD with the same authorization. No redirect to CDN. No access JWT in an audio URL. Do not expand the existing cover-token behavior as part of this change.

For a ready matching file fingerprint, new direct responses advertise `download_binding:'if-match'`, full SHA-256 content_version and exact content_length; otherwise all three fields are null. CDN responses use `download_binding:'immutable-path'` and matching length/hash. These additive fields are a transfer capability declaration, not an ETag obtained from a separate HEAD. Clients absent this declaration (including old servers) stream only and decline new persistent cache admission (§6). At issuance recheck the fingerprint under the track lock; replacement after that point is handled by the transfer precondition, not an assumption that the descriptor stays current.

CDN returns `https://media.puuk.fun/cdn/audio/<id>/<64-lowercase-hex-sha256>?md5=<token>&expires=<epoch>`, TTL 1800 seconds. The delivery service alone owns provider signing, selection, safe file/version lookup and expiry; clients never implement signing. Unversioned/unverified files receive direct immediately and enter bounded version preparation, rather than being hashed in Play. There is no synchronous provider control-plane call during Play.

All ticket responses, including 4xx/5xx, use `Cache-Control: no-store, private`, `Pragma: no-cache`; fetch uses `cache:'no-store'`. No CDN, reverse proxy, service worker or persisted query cache may cache the endpoint. `WWW-Authenticate: Bearer` accompanies session 401. Errors preserve `detail` compatibility; new errors may add `detail:{code,message}`. Codes: `forbidden` 403, `track_unavailable` 404, `delivery_busy` 503 with `Retry-After: 1`; validation remains 400/422. Errors contain no URL, filename, secret or provider response body.

## 3. Actual-byte content identity and lifecycle

`content_version` is SHA-256 over the **entire served file**, including embedded tags/cover, not decoded PCM, catalog version, cover_version, path, size/mtime alone or Qdrant metadata. Persist it with a verified fingerprint `(st_dev, st_ino, st_size, st_mtime_ns, st_ctime_ns)` and readiness state in additive SQLite delivery tables. Retain a per-track issued-version ledger independent of cascading track deletion. Do not overload the word-lyrics `audio_sha256` column, whose semantic scope is separate.

Hash in fixed 1 MiB chunks from an open safe regular-file descriptor; pre/post `fstat` must match, path must still designate the expected file at publication, and symlinks escaping the real `MUSIC_DIR` are rejected. On change, discard result and mark pending. No full-library hash on startup or Play. One hash owner across API processes supervises a killable hash subprocess, as specified in §4.5; durable deduplicated pending IDs are capped at 10,000, attempt wall-time is 120 seconds plus bounded termination grace, at most two attempts with 5-second delay. Terminal failures remain direct and observable. Scanner/import enqueues preparation after catalog commit; it does not hash synchronously. Large files that exceed the limit stay direct; no stat-based substitute for SHA-256. Resume/retry of failed preparation is an explicit bounded scan operation, not another Play retry.

For each GET/HEAD on the protected origin, compare current fingerprint with the persisted ready version. Open the descriptor used to stream while holding the same mutation lock used to replace files, verify descriptor identity before headers, and release lock after the descriptor is pinned. Stream from that descriptor; do not reopen by pathname later. Atomic replacement leaves already open old inode/bytes stable. There is no old-version filesystem archive: after replacement an old path/version cache miss returns 404, never new bytes under an old hash. A new stat/fingerprint mismatch marks version pending and returns 404 from the versioned origin; direct remains authorized and usable. Supported writers publish by atomic replacement; unmanaged in-place external writes during streaming are unsupported and require taking that file out of service first. A rename/replace cannot overwrite a cached object's meaning.

| Mutation / entrypoint | Required handling before CDN can issue again |
|---|---|
| Bot publishes via hardlink; initial/new scan; manual library import | Backend ingest computes hash only after publication is complete, independent of bot provenance hashes. No bot changes required. First unknown fingerprint is direct until ready |
| Scan update, `media_locations` discovery/Qdrant recovery, metadata GET reconciliation, explicit resync | Verify actual file/fingerprint, invalidate differing ready state, compute through the same version owner. Never trust Qdrant size/hash as authoritative. Tombstones precede any recovery |
| `safe_replace_audio_file` from track tags/title/genre/lyrics/embedded art; whole-album edit and partial success | Mark unavailable-for-CDN and reserve retirement/purge intent **only for exposure satisfying §9** before replacement. Commit changed metadata/journal and pending version, then enqueue hash preparation. Each successfully changed file gets its own version; failures retain old version only if bytes/fingerprint actually match |
| Crash at prepared/replaced/committed journal stages | Reconciliation verifies the actual inode/bytes, restores a matching ready state or pending, and durably retains the old purge intent. No ticket during uncertainty |
| Database-only artist credits, favorites, loudness results, recommendations, external artist artwork | No audio-byte/version change. Loudness is client-side; no server variant/transcoding is introduced |
| Out-of-band replace at same path, including same size/restored mtime | ctime/inode fingerprint invalidates; rescan computes actual hash. Old hash is never served with changed bytes |
| Delete/missing file, including deletion service partial failure | Persist tombstone and retire version; only if §9 exposure exists persist required purge intent before destructive work. Stop new tickets/origin immediately. Finish existing file/Qdrant/DB cleanup idempotently; do not resurrect from Qdrant. Never-enabled/direct-only mutations require no optional purge capacity |

Originals are not rewritten for CDN, hashing, normalization, testing or warmup. This contract observes the existing explicitly requested metadata editing mechanism; it does not authorize any real metadata edit. An unsupported writer or newly found mutation path blocks its CDN eligibility until integrated and reviewed.

### 3.1 Canonical ingest operation and every active caller

`services.media_locations.ingest_music_file(file_path, *, source, expected_track_id=None, payload=None, deadline=None, cancel=None) -> TrackRow | None` is the sole high-level **creating ingest** operation. source is `import` for explicit/scan disk discovery, `recovery` for restoring a specific existing/requested ID. It resolves a safe file and extracts needed file metadata **outside** a SQL transaction, then obtains bounded track/path locks and revalidates that fingerprint. It claims identity through the one canonical identity operation `repositories.share_entities.claim_track_identity(conn, rel_path, source, expected_track_id) -> canonical_id | None` before album identity resolution, metadata/artist-credit **writes**, queue/Qdrant publication or any other ID-dependent write. Identity/path claim, registry and initial track/album/metadata rows commit atomically; all touched ingest repository helpers accept the caller's conn instead of opening independent commits. No network/file parsing/hashing is allowed while the SQL transaction is held. A returned row always contains the canonical `row['id']`; callers must replace their candidate ID with it. None means no catalog/album/Qdrant write under the candidate. No silent substitution inside the old void-returning `add_or_update_track`.

Identity rules under a BEGIN IMMEDIATE transaction: normalize safe root-relative path; reuse its one live claimed ID for import. For an unclaimed path, use the historical UUIDv5 candidate only if never registered/deleted/aliased; otherwise allocate fresh UUIDv4 and claim it. Deletion retires its live path claim transactionally while retaining the ID tombstone; thus later same-path import is allowed without identity reuse. Repeated import of that path reuses the new ID. Recovery never allocates a replacement ID or follows a tombstone/alias into a newly created row: requested ID must not be deleted/aliased, and an existing path claim must match it exactly. A legacy unregistered requested UUID can be restored only if its safe path is unclaimed and no conflicting/tombstoned identity would be reused. Unknown/tombstoned old Qdrant IDs cannot replace a current same-path import. Registry/path uniqueness failures roll back and retry **once** by rereading identity within the remaining operation deadline. Existing void-returning upsert functions guard creation through the **same** claim operation in specific-ID recovery mode: an exact never-used legacy ID/path can be registered, but the returned ID must equal the caller's ID; otherwise raise `identity_not_claimed` before any write. This preserves trusted repository/test callers without silently allocating a different identity. Tombstones/aliases/conflicting path claims always reject. Normal metadata updates of existing rows preserve the ID.

| Active writer/caller | Required canonical-ID consumption |
|---|---|
| HTTP `/api/library/scan` → `services/library_service.scan_library` | Replace local UUID-before-album sequence with ingest(source=import); use returned ID for file-change/loudness follow-up and queue bookkeeping |
| Startup empty scan and `library_service.sync_missing_tracks_to_db` disk phase | Same import operation, including repeated same-path reimport; startup must not pre-filter solely by historical UUIDv5 |
| CLI `brain/scan.py`, including `_index_scanned_file` | Ingest first; all subsequent SQLite/Qdrant/embedding IDs and payload publication use returned row ID, not locally computed point_id |
| `media_locations.ensure_track_from_file` | Thin compatible wrapper around import when no ID is requested; with an explicit requested ID it uses recovery rules; returns the canonical row or None |
| `media_locations.ensure_track_in_db`, startup Qdrant phase, metadata/resync and streaming/ticket recovery callers | Specific-ID recovery only; check registry/path claim before network and again before commit; propagate returned row ID, return unavailable for rejected requested ID. Full tag parsing is not required on the bounded Play recovery path; use verified safe-file plus payload metadata and defer full resync |
| Bot hardlink publication | Bot performs no identity claim; next backend HTTP/CLI/startup disk ingest owns the ID. No bot edits |
| Optional `loudness_sync_service._create_track_from_payload` | Audited but **no edit** to this service: normal periodic path is create_missing=False. Its existing safe-file/stat validation precedes lower-level upsert; that guard calls the canonical identity operation in specific-ID recovery mode and accepts only the exact returned ID. Tombstone/alias/conflict rejects with no writes and the existing per-item sync error handling reports failure. Automatic filesystem-move matching is removed from v1. Supported **track metadata rename** and album rename/merge preserve identity (§7); an unmanaged path move is delete/import discovery, not an inferred identity merge. No hashing/inode matching of duplicates or new operator-mapping API is introduced. Tests exercise HTTP scan, both startup phases, CLI publication, Qdrant restore, optional loudness rejection and repeated tombstone/same-path import.

## 4. Protected origin, canonical requests and HTTP

### 4.1 Routing and origin authentication

Use `origin-media.puuk.fun` on the **existing** server/IP, with its own valid TLS certificate and nginx server block. Configure the CDN's upstream **Host and TLS SNI both as `origin-media.puuk.fun`**, origin protocol HTTPS, certificate validation on, redirects/follow-redirects off. Keep `web.puuk.fun` DNS independent of CDN; preserve the media validation CNAME/certificate. Host `media.puuk.fun` alone cannot isolate requests whose configured upstream Host is still `web.puuk.fun`.

The dedicated origin vhost proxies only `/cdn/audio/` to the loopback backend, has a default `return 404`, no SPA fallback, static alias, auth/admin/catalog routes or file browsing. Explicitly deny `/cdn/` in the web vhost. Reject Host/SNI mismatch and unrecognized authority within the Puuk origin listener without changing unrelated vhosts/global defaults. The IP/default-vhost and spoofed `Host`/`X-Forwarded-*` matrix is a live gate. Host/SNI route traffic; they grant no authorization. Use scoped proxy connect timeout 2 seconds and read/send idle timeouts 15 seconds; these are no-progress limits, not a total recording-duration limit. The 2.5-second **response-admission budget**, underlying blocking-call limits and late completion rules are defined in §4.5; it is not a claim that cancelling an await forcibly stops a Python thread.

CDN sets `X-Puuk-Origin-Secret` as a static request header, overwriting all client instances. Backend accepts exactly one header with a bounded 64-character ASCII value and uses `hmac.compare_digest` against configured secret bytes. Missing, wrong, duplicate, comma-joined, oversized or empty values fail 403; origin off fails 404. No fallback to JWT, signature query, Host, forwarded headers, source IP, Referer or User-Agent. Nginx must not inject the correct secret for arbitrary internet callers and must not contain an authoritative plain string comparison. Strip user Authorization/Cookie before the protected backend hop; never return the secret in any response. The backend remains loopback-bound.

S5 must prove overwrite by sending forged/multiple client header values through CDN on a cold fixture and observing **only boolean equality and header count** at origin; never print the received or configured value as J1's raw-value suggestion would do. Wrong client value must not reach origin as authoritative input. If the provider appends instead, this mechanism fails G3; do not ship by accepting multiple headers.

### 4.2 Path, query and token

The only object route is `/cdn/audio/<canonical-uuid>/<sha256>`, exactly two components after prefix, no extension or trailing slash. Canonical identifiers use ASCII lowercase; content hash has exactly 64 lowercase hex digits. Validate the raw request path before decoding/rewrite at nginx and backend: reject percent escapes, backslashes, encoded separators, NUL/control characters, dot segments, duplicate slashes, extra segments and noncanonical spelling; do not redirect these variants to a signed object. Resolve only a database-selected file and version; no path or URL parameter can select the filesystem path. Disable automatic trailing-slash redirects on the protected route.

For signed GET/HEAD query require exactly one `md5` (22 URL-safe Base64 characters, no padding), and one `expires` (canonical positive decimal Unix seconds, no plus/leading zeros; bounded to 10 digits). Order is immaterial. Reject duplicate keys, empty values, unknown parameters (`mt`, `token`, `v`, filename, URL, cache busters included), percent-encoded key/value aliases, malformed escapes, `;` separators and oversized raw query (>128 bytes) with 400/403 and no audio. Origin validates the same syntax; CDN-generated internal Range/slice state is a header/cache implementation detail, not an accepted public query. Query carries no user ID or IP.

Provider formula, UTF-8/ASCII bytes, no newline:

```text
message = decimal(expires) + exact_path + " " + CDN_SIGNING_SECRET
md5 = base64url_without_padding(MD5(message).raw_digest)
url = CDN_BASE_URL + exact_path + "?md5=" + md5 + "&expires=" + decimal(expires)
```

This is Yandex's no-IP protocol, not a new HMAC design. It signs the full path including track and hash; the host and extra query are not signed. Use only the configured hostname and canonical path. Primary source: [secure tokens](https://yandex.cloud/ru/docs/cdn/concepts/secure-tokens). J3 checks an independent fixed synthetic vector and exact-path/expiry mutations; no real secret in fixtures.

CDN must validate token/expiry before **every** GET/HEAD cache response, including 206/304. Edge cache key excludes **only** `md5` and `expires` using `queryParamsBlacklist`; all other query bytes remain key material and origin rejects them, preventing a valid bare-object HIT from bypassing origin query validation. Never use “ignore all query”. Duplicate token parsing and normalized path/query variants require cold and warm negative probes; any audio for rejected input blocks release. No unsigned alternate CDN hostname/resource may expose the same cached audio. Server clock must be synchronized; documented no-IP behavior is tested through Wi-Fi/cellular transition.

### 4.3 Bytes, methods, CORS and cache policy

GET full response is 200 with actual MIME type, stable strong `ETag: "sha256-<hash>"`, exact `Content-Length`, `Accept-Ranges: bytes`, identity encoding, no audio transforms/compression or `Set-Cookie`. Single ranges beginning/middle/end/open-ended/suffix return exact 206 and matching Content-Range/length. Unsatisfiable range returns 416 `Content-Range: bytes */<total>` without audio. Preserve baseline invalid Range 400. Multiple ranges retain installed Starlette's correctly framed multipart/byteranges 206 behavior; J3/S5 must verify boundaries, lengths and bytes, never return unrelated full bytes as a fake 206. Matching If-Range yields 206; mismatched validator yields full 200; conditional HEAD/GET 304 carries no body and still requires access.

Explicit HEAD uses the same file/version and access checks, reports full-object headers with no body (ignores Range); it cannot warm or read an unauthorized object. OPTIONS returns 204 with no body/file lookup or catalog metadata for a syntactically valid protected path/query and allowed browser origin/method/header set. It needs no **client Bearer**. At the edge, OPTIONS to an actual signed URL must succeed; unsigned OPTIONS may be rejected 403 by the secure-token layer and is not an authorization bypass. At origin, OPTIONS still needs the CDN secret. No method besides GET/HEAD/OPTIONS is allowed (405, Allow set). Preflight responses are not audio-cache entries. Native requests may omit Origin. CORS is a browser policy, not authentication.

Exact production web origin is `https://web.puuk.fun`. Return `Access-Control-Allow-Origin` with this constant, never reflection or `*`, and no `Access-Control-Allow-Credentials`. With a different Origin return no matching ACAO; preflight returns 403. Allowed methods GET/HEAD/OPTIONS; request headers `Range, If-Range, If-None-Match`; expose `Accept-Ranges, Content-Range, Content-Length, ETag, Last-Modified, Age` and the observed provider cache-status header documented by S5. Preflight Max-Age 300. CORS headers apply to edge-generated 403 and origin 400/404/405/416/5xx as well as audio. The provider CORS option supplies only ACAO; origin/static response settings must supply the rest. Local origins exist only in a separate dev profile, never added to production cache. Fixed ACAO prevents Origin-dependent cache poisoning.

Version-bound direct cache transfer: GET `/api/stream/<id>?mt=...` with `If-Match: "sha256-<descriptor-hash>"`, no Range/If-Range, must compare the single exact strong validator to the **current ready hash and fingerprint of the descriptor pinned under the mutation lock**. Mismatch, unknown/not-ready hash, malformed/multiple/weak/wildcard If-Match, or Range combined with this cache precondition returns 412, no bytes, no-store. On match return the full pinned file as 200, strong hash ETag and exact length; preserve the pinned descriptor until completion/close. Concurrent atomic replacement after pinning leaves the old matching inode readable; replacement before pinning yields 412 even if equal length. A preliminary HEAD cannot authorize admission. Ordinary direct streaming without If-Match remains compatible and may use unversioned files; it makes no cache-verification promise. This conditional path does **not** hash a file during GET. S2 owns precondition handling and pinned response, S4 owns the transfer; J3 tests both sides of the replacement race.

Web sets `audio.crossOrigin='anonymous'` **before** assigning each source, uses streaming src directly, no full-file blob. Verify existing gain/analyser graph and normalization. CDN player/download sources have no Puuk Authorization/Cookie headers; credentials mode is omit. API requests go only to configured API origin. Returned unexpected host, userinfo, port, HTTP downgrade, redirect, path or query fails validation; never attach auth before this check. Direct iOS Bearer headers are assembled afresh for the exact configured API origin, never reused from a previous source. No guarantee about AVFoundation stripping on redirect is assumed; no delivery endpoint redirects, and rebuilt-device capture must show no JWT leak.

Client-facing audio responses (CDN and direct, including errors) are `Cache-Control: private, no-store`; browser cache duration is disabled/zero. Edge uses separate custom success-only TTL **3600 seconds** for versioned audio 200/206, with stale-on-error/updating disabled and all error/redirect/OPTIONS TTLs zero. Cookie content is ignored, request cookies are not used for representation/access; no cookie/Authorization varies bytes. Use provider cache settings/response-header rules to preserve client no-store while caching only successes. If the real resource cannot prove that separation, no pilot; do not change browser policy to public. CDN's Range representation/slice key must preserve correct bytes. Start with slicing off; enable on bounded >10 MB fixture only after separate byte/range/ETag/purge proof. Slicing changes require G3 recheck. Cache HIT requires observed provider evidence **and** reduced origin reads, not a generic 200/node header.

Keep exported `api.app` as the existing FastAPI object, its dependency overrides and router registration compatible. In FastAPI's assembled stack the order is `ServerErrorMiddleware → DeliveryBoundaryMiddleware → ExceptionMiddleware → router`. DeliveryBoundary owns a `CORSMiddleware(inner_app, <baseline account options>)` instance **only for its default account branch**; it does not wrap the whole dispatcher. Thus the current account credential/method/header policy remains unchanged outside the paths below, and cannot answer a protected media preflight first. No second app/lifespan/router framework is introduced.

Path selection uses raw path plus exact decoded path classification, no client-supplied forwarded route: all `/cdn/` paths enter protected branch (noncanonical/nonobject paths fail 400/404), exact `/api/media-ticket` enters ticket branch, `/api/stream/` prefix enters direct branch, `/api/share/` prefix enters share no-store branch. Failed path/ID/method matching stays in the chosen policy and returns no-store JSON, not the account default or SPA. Order inside each branch:

1. Establish a response-start guard/correlation ID and applicable deadline before reading body, scheduling dependencies or awaiting any operation. Limit ticket JSON body to 4 KiB and Authorization to 8 KiB; oversize returns 413/400 with the same error policy.
2. For protected origin **first** check enabled state and exact single bounded secret header using constant-time comparison, then canonical path/query validation, before preflight or route lookup. Missing/wrong/duplicate secret OPTIONS returns 403; origin off returns 404. No global CORS middleware can bypass this step.
3. Handle recognized browser OPTIONS in this boundary (204 allowed Origin/method/headers; 403 otherwise; no entity/file lookup). Protected allow headers remain Range/If-Range/If-None-Match; direct additionally permits Authorization and If-Match, methods GET/HEAD; ticket permits POST and Authorization/Content-Type. The boundary advertises OPTIONS as well, Max-Age=300, and exposed headers per §4.3. No client Bearer is required for protected preflight; direct/ticket preflight has no account dependency. Share uses GET and Authorization, no-store. No Access-Control-Allow-Credentials on any of these branches. Absent Origin native requests proceed; disallowed simple Origin gets no matching ACAO.
4. Delegate nonpreflight requests to the **inner** ExceptionMiddleware/router, using the same async operation owner in §4.5 for media auth/file work. Intercept every `http.response.start`, remove downstream CORS credentials/ACAO/cache directives and append the branch's exact CORS and no-store policy. This includes dependency 401, request validation 422, unknown 404, 412/416 and handler 500, not just successful responses. Ticket/share add Pragma=no-cache. Do not run the account CORS instance on these paths.
5. Catch unhandled exceptions **before response.start** inside this boundary and emit sanitized 500 with the same CORS/no-store headers. If a streaming exception/disconnect occurs after start, close descriptor, terminate that body/connection and count an error; never send a second start or replace it with HTML. FastAPI's outer ServerErrorMiddleware is therefore not relied on to add media headers. Default account paths delegate unchanged to account_cors(inner_app) and retain its prior exception behavior.

Local J3 tests must invoke the fully assembled `api.app` with isolated startup services, not a stand-alone streaming router. Include a neighboring account route preflight to demonstrate its old policy is intact. ### 4.5 Bounded execution, lock ownership and shutdown — S2 owner

Media request deadline scope is ASGI entry to response headers: ticket, direct and origin branches have a 2.5-second response-admission budget (share resolver remains its 5-second client budget). Media routes/dependencies are async entrypoints; all synchronous account lookup, JWT verification, track/registry lookup, safe stat/open, signing/ledger transaction and optional one-shot Qdrant recovery run as **one** admitted work item in delivery_service's dedicated executor, maximum 4 running items/API process, **zero queued items** (acquire a nonblocking semaphore before submit). Do not run default FastAPI sync dependencies first and thereby bypass admission. Full lanes return 503 Retry-After:1. On ASGI timeout/disconnect set the item's threading.Event cancellation flag and suppress any later result; if no response has started return 503 no-store. Retain the lane until its actual function finally returns; no replacement thread is spawned for a timed-out item. Check remaining monotonic budget/cancel flag before and after every external step and before issuing/publishing a URL. The work item owns any opened descriptor until an explicit successful handoff to the ASGI response; discarded late results close their descriptor in finally, never leave it to GC.

`repositories/base.py` gains an opt-in deadline/cancel context and `get_connection(deadline=None, cancel=None)` override; the default without context keeps its existing behavior. Propagate that context into the owned work item, including `get_current_user`/media-ticket user lookup. Media connections use SQLite connect and PRAGMA busy_timeout **min(100ms, remaining)**, progress handler every 1000 VM steps to abort on deadline/cancel, and no automatic SQL sleep/retry. All touched media-path reads, especially `repositories/users.get_user_by_id`, close cursor/connection in finally; never leave a timed-out transaction held until GC. Bound each registry/path/permission transaction to remaining budget, release on rollback/exception. No network or file hashing occurs with a SQL transaction held. Idempotent identity/exposure commits that already completed before a timeout cannot be undone; conservatively retain their registry/exposure state even if no URL reached the client. Late work may not send a response, clear a tombstone, publish a stale hash or start client playback.

`metadata.track_mutation_lock` gains an optional absolute deadline/cancel argument using `threading.Lock.acquire(timeout=...)` and `flock(LOCK_EX|LOCK_NB)` polling at up to 10ms within the same budget; the small lock-registry guard is included in that budget. Default existing editor behavior remains unchanged when no deadline is supplied. Delivery descriptor/issuance operations cap total two-level lock wait at **100ms**, preparation pinning at 250ms; on timeout they release anything acquired and return 503/direct preparation defer. All descriptor and managed mutation/version-exposure paths use the same track lock. Import adds a controlled `ingest-path-<sha256(root-relative-path)>` key through this same lock primitive before choosing/locking the canonical track ID; no raw path as lock filename. Lock order: path lock if needed → track lock → short SQLite transaction; never acquire those locks from inside a DB transaction. Sorted IDs for existing album multi-track workflows, one track per bounded critical section, no new global catalog lock held over audio IO. Fingerprint/stat under a pinned descriptor precedes the short commit, and holding the track lock prevents managed replacement between validation and exposure/precondition commit.

Play recovery gets **at most one** Qdrant retrieve with a dedicated per-item client, configured timeout=1 second, transport retries disabled; no shared recommendation client/timeouts are modified. Begin it only with at least 1 second of response budget left. Use only the expected ID, safe file and minimal verified payload; full tag reconciliation runs later. Pass the same deadline/cancel into recovery/ingest; check tombstones/path claim before and after retrieve. Close the dedicated client in finally. An opaque DNS/kernel stall can outlive its library timeout, so the ASGI timer bounds response publication while its one occupied executor lane remains quarantined. Busy/full preparation never starts a hash or control-plane request in Play. No claim that `wait_for` cancels a blocking syscall is permitted.

Streaming admission is separately capped at 16 open pinned descriptors/API process. Acquire before response headers, otherwise 503; HEAD, normal finish, invalid range/precondition, disconnect, timeout or error begins cleanup. Reads are 1 MiB maximum in a separate 4-thread read pool with at most one queued read per admitted stream (finite at 16), no 2.5-second total recording limit after headers; a 15-second no-progress read/send deadline stops the response. A late blocking read retains its pool slot **and stream admission/descriptor ownership** until it really ends, discards its bytes after cancellation, then closes its descriptor/releases admission; never close/reuse its FD concurrently or free a slot to create unlimited replacement streams. No extra pools. These limits multiply by the actual API-worker count recorded in the runbook, not an imaginary global semaphore.

Hash isolation: each API process may try nonblocking flock ownership of DELIVERY_LOCK_DIR/hash-owner.lock; only the winner schedules hash jobs. It supervises **one subprocess per hash attempt**, launched by the existing interpreter as `-m services.content_version_service --hash-job <nonsecret-job-id>` with shell=False, no API app/Qdrant import, and minimal environment containing only required interpreter/DB/music-directory settings (no signing/JWT/origin/provider credentials). Pass the flock FD explicitly using POSIX pass_fds so both supervisor and child retain ownership; a crashed supervisor cannot release the lock while its child is still running. No standalone daemon/systemd unit or agent worker is added. Child reads/pins the named safe file under 250ms track-lock budget, releases the track lock, hashes the pinned descriptor in 1 MiB chunks, and emits at most 512 bytes of structured hash/fingerprint result (no paths/secrets). It performs **no DB writes**. Parent starts the 120-second attempt timer before spawn, validates result/fingerprint/path/current job fencing token under track lock before a short DB publication, and never publishes a result after timeout/cancel. No SQL transaction or application track lock is held during hashing.

At hash timeout or shutdown send terminate, allow 2 seconds, then kill, allow 3 seconds to reap. Do not release flock or start a replacement attempt until child exit is actually confirmed. If process creation or an uninterruptible OS operation exceeds this grace, mark preparation unavailable/direct-only, alert and retain ownership/one occupied slot until real exit/operator termination; **the 120+5 seconds is the application stop protocol, not a hard kernel scheduling guarantee**. Each owner uses one dedicated supervisor thread to spawn/wait/stop its one child; never block the ASGI event loop on Popen/wait. The event-loop timer sets a stop flag; a spawn returning late must immediately stop/reap its child and cannot publish. Control SQLite work uses opt-in 100ms/deadline connections outside the request executor, max one control item/owner and no unbounded control queue; a timed-out control item retains its slot until real completion. Durable job leases are 60 seconds and renewed every 10 seconds under an owner/fencing token; a lease alone never authorizes a second hash process while the flock is held. If renewal fails, stop child, discard result, and leave job for reconciliation after confirmed exit. A parent-death child checks getppid/deadline between chunks and exits; inherited flock still prevents overlap if a syscall stalls. A new owner after real exit reclaims expired jobs, at most two finite attempts total.

Purge uses independent DELIVERY_LOCK_DIR/purge-owner.lock and a 60s fenced lease (renew every 10s **throughout polling**, not just submission). To avoid an unkillable network thread, each HTTP operation runs in one supervised subprocess of cdn_purge_service, total deadline 10 seconds, urllib/TLS connect and individual IO timeout at most 2 seconds or remaining time, no transport retries; parent applies the same terminate/reap protocol and never overlaps another request before confirmed exit. Inherit its owner FD by pass_fds just as for hashing. Stdin ≤8 KiB carries request/credentials in memory (never argv), minimal child environment excludes unrelated secrets, provider response ≤64 KiB, output is only validated operation ID/status/sanitized reason ≤4 KiB; raw body/headers/stderr are not logged. Restrict targets to official CDN/operation API endpoints constructed from validated IDs, TLS verification on, redirects off. Persist submitting/attempt/rate-limit reservation before sending. Timeout after possible submission is **ambiguous**, retains exposure/outbox intent and consumes one attempt; later purge resubmission is safe and rate limited, never declared succeeded. No new Python/network dependency is required for these subprocesses.

Shutdown: stop admissions and schedulers first; cancel request work via flags, drain up to 5 seconds without releasing live lane/descriptor ownership early, close completed streams/connections, stop/reap hash and purge children as above, then release only resources whose work has ended. If request/read threads or children remain blocked, keep their resources/ownership and report unclean shutdown; process supervisor/operator termination is required, not a falsely successful restart. Pure Python cannot guarantee recovery from uninterruptible OS IO. Subsequent workers fail fast on held ownership and serve direct where possible; never spawn unlimited replacement work. J3 tests held track/DB locks, full executor/stream pools, timeout followed by late result/commit, two API owners, lease loss during polling, blocked child kill/reap, and clean/unclean shutdown with injected controllable stalls. These are executable future tests, not S1 proofs.

## 5. Permission lifetime, budgets and playback recovery

### 5.1 Local time and bounded caches

At ticket-request start capture a monotonic time `m0`. At receipt validate numeric types, `0 < expires_in <= 1800` (direct legacy at most configured sane cap 86400), and new-server equality `expires_at - server_time == expires_in` within one second. Define:

```text
usable_until = m0 + max(0, min(expires_in, expires_at-server_time) - 30) * 1000
reuse_until  = min(usable_until, m0 + min(cache_for, 30) * 1000)
```

Subtracting the **whole** request time by using its start is conservative. The 30-second margin covers clock/edge skew and issuance truncation; expiry decisions do not use client wall-clock epoch. On baseline responses without server_time, use request-start plus `expires_in - 30`, ignore wall-clock expires_at for reuse, and apply the same maximum 30-second reuse lease when cache_for is absent. A response received after the computed deadline is unusable. Reject malformed/implausible responses; no Date.now clock rollback extends a capability. No persisted permission cache: restart, tab suspension visibility return, iOS foreground/wake or monotonic reset clears remote permissions regardless of deadline; keep an already healthy playing source until it needs a new request. Native background errors use the same bounded recovery, not an assumption about clocks advancing in sleep.

Permission cache max 200 LRU entries/platform, TTL as above, keyed by normalized backend origin + account ID/auth generation + track ID + known content version + requested mode + delivery epoch. Pending requests deduplicate on the same key, max 8 total, current track gets priority and can cancel queued preload work; excess speculative work is shed. Never log/store a raw token as cache identity; auth generation changes on every token/session change. When version/epoch changes evict conflicting entries; remove terminal errors instead of negative caching. Resolve prefetched permission again at actual source use if its lease has expired.

Long recordings use the same 30-minute capability; do not make a public link or extend TTL to duration. Provider documentation permits finishing an already started transfer after expiry, but later Range/reconnect/seek may need renewal. Do not swap a healthy source on a timer. On resume/seek/repeat that requires a remote request after usable lifetime or foreground, acquire a fresh capability, replace once if needed, restore position and intent. A multi-hour recording is supported through this recovery, with a possible bounded interruption; seamless continuation is a measured device/browser gate, not a promised property. Unknown duration does not cause unbounded TTL. Pausing beyond TTL never leaves a stale capability silently reused.

### 5.2 One owner and finite attempts

Web player store owns recovery; iOS existing PlaybackCoordinator owns it. Ticket helper, AudioEngine, scheduler and cache do not independently retry the same playback failure. Per user Play/Retry or one interruption episode:

| Phase | Maximum |
|---|---|
| Ticket HTTP request | 3 seconds each, no internal retry |
| Initial source startup or stalled-source detection | 7 seconds without readiness/progress |
| Permission refresh | one request, one source retry (3 + 7 seconds) |
| Direct fallback | one direct request, one source attempt (3 + 7 seconds) |
| Overall episode | **30 seconds**, including requests, source replace/seek/readiness and compatibility negotiation; remaining time bounds every later phase |

At most 3 ticket calls and 3 source attempts; endpoint-negotiation consumes a slot. Existing iOS recovery paths must consume this same ledger, including unexpected native URL resets. A native stack can issue multiple byte ranges internally; the application attempt limit does not falsely promise a wire-request count, but unload/cancel the source at its timeout. Healthy playback has no absolute duration timeout. Once exhausted, stop automatic recovery for that selection, show a stable error and explicit Retry; do not reset the ledger because an error re-fired or network toggled. New user action/new track creates a generation. Auto-advance creates a new track generation without replaying a failed source forever.

| Signal | Action |
|---|---|
| Ticket API 401 | Stop, clear auth/session sources, show existing login flow. No refresh/fallback bypass |
| Ticket API 403 or track 404/410; invalid URL/DTO | Terminal unavailable/security error, no direct bypass |
| Ticket API 429, 5xx, timeout | No automatic ticket retry; stop with appropriate retryable UI. A successful ticket is required before automatic audio fallback |
| Observable expired/invalid CDN permission or opaque browser media failure | Once reauthorize via ticket API. If refresh is CDN, try once; if direct, treat it as the single direct fallback |
| DNS/TLS/network/CDN 5xx, refreshed CDN still fails | One explicitly authorized direct fallback; TLS validation stays on |
| Direct-selected initial response | No later redundant “fallback to direct”; at most one expired-permission refresh, then terminal |
| Decode/unsupported-format error, confirmed invalid range | Terminal format/seek error; do not loop delivery modes |

Web media errors do not expose reliable HTTP status. Record `opaque_media_error`, use available engine/network signals and the ticket result, and never label an imagined 401/403. Generic CDN failure can spend the one refresh and one direct fallback; permission/API denial cannot.

For every await/source event check `{authGeneration, serverEpoch, selectionGeneration, sourceAttempt}` before cache insertion, source assignment, seek or state changes. Preserve current track, queue, playback position, playing/paused intent, speed and loudness gain during a source recovery. User pause while refreshing wins. A late A cannot replace B; logout/token/server change invalidates every outstanding phase. Listen/history/play-start events belong to the logical playback, not each source replacement; do not double count.

On logout/confirmed session 401: increment auth generation first, abort tickets/downloads/recovery/preload, stop and unload remote **and local** players, clear queue/current protected metadata/permission caches, detach MediaSession/lock-screen sources, then render auth gate. Late completions cannot revive playback or write a permission/cache manifest. Network/5xx alone do not log out or delete offline data. Cross-tab web logout uses existing storage events or an explicit session broadcast wired by S3.

Do not inspect nonexistent download ETag/status properties or parse localized error text. No expo-crypto, SHA library, native patch, dependency upgrade or whole-file JS read is authorized. New persistent-cache transfers are foreground-only: on AppState leaving active, cancel and generation-fence them before suspension; foreground/wake also invalidates any leftover transfer even if a clock excluded sleep. Transfer failure, null/paused result, partial file, bad binding, unknown length/version or old server means delete/ignore temp, **decline persistent admission and stream only**. It never means admit by length alone. SDK success plus exact local size is a completeness check after a bound transfer, not a cryptographic local digest; post-transfer disk corruption is outside that guarantee and must not be described as hash verified.

Each attempt's existing 120-second total includes its final admission; allow at most the remaining time and 5 seconds for File.size/atomic move/manifest publication after native completion. ## 7. Permanent entity identity and authenticated resolver

### 7.1 URLs and parsers

Canonical outgoing URLs are exactly:

```text
https://web.puuk.fun/track/<track-id>
https://web.puuk.fun/album/<album-id>
https://web.puuk.fun/artist/<artist-id>
```

Track IDs are lowercase canonical UUID strings (existing UUIDv4/v5; do not mandate v5). Album IDs are positive SQLite integers represented as canonical decimal strings, max signed 64-bit; keep as strings/BigInt for parsing, never unsafe JS Number conversion. Artist IDs are `art_` plus 32 lowercase hexadecimal characters; reserved “various artists” has no shareable artist ID. Never construct IDs by hashing names in a client. Format from the server's lossless `share_id` (defined below) using `encodeURIComponent` once; canonical formats need no escapes. Legacy DTO IDs may be used only when strings validate or numeric IDs are positive safe integers; unsafe numeric values show a share-unavailable error rather than formatting rounded IDs. No slug, track title, file path, token, signature or arbitrary base URL.

Parser accepts only this production HTTPS origin and exact allowlisted path; internal parser may accept a root-relative canonical path. No userinfo/alternate port, protocol-relative URL, custom scheme, backslash, percent-encoded separator/double decode, dot segment, duplicate slash, trailing segment, query or fragment. Reject rather than redirect noncanonical/malformed input. Optional one trailing slash may be normalized with replaceState only after successful ID validation; formatter never emits it. Album zeros/sign/exponent/overflow fail. Navigation state stores only `{type:'track'|'album'|'artist', id:string}`, not the original arbitrary URL. No `returnTo` query is interpreted.

### 7.2 Identity stability, rename, merge and deletion

Add a durable registry keyed `(entity_type, public_id)` with state active/alias/deleted, canonical target of the **same type**, created/changed timestamps; backfill existing entities idempotently. IDs/aliases/tombstones are never reused or removed automatically. Registry is not cascaded away with entity rows. Alias resolution checks a maximum of 8 links, rejects cycles/cross-type targets, and compresses chains transactionally on merge so ordinary resolution is one hop. Broken chains produce unavailable, not a fallback name search. New versions of metadata may change display text but not a public ID.

Track metadata title/artist/album edits preserve track ID. Every scanner/creator uses the canonical ingest/returned-ID rules in §3.1, including actual library_service HTTP/startup paths. Unmanaged filesystem moves are delete/import discovery and outside supported entity rename in v1; no automatic hash/inode matching or operator-mapping API is added. A deleted UUIDv5 may not be reused by later same-path import: allocate a fresh UUIDv4, persist path identity, leave the old tombstone. Qdrant/optional loudness restore checks registry/path claim and cannot revive a tombstone/alias or substitute an identity under its caller.

Album rename without collision preserves its integer ID. Existing `merge_album_into(source,target)` must record source→target alias in the **same transaction** as source deletion, including aliases already pointing at source; explicit empty-album deletion creates tombstones, not a redirect to an unrelated album. Partial album edits preserve the original entity for remaining members; only the successful explicit merge redirects. Old links resolve target metadata and the UI replaceStates the canonical target URL, without adding a redirect history entry. No unauthenticated HTTP redirect reveals the target.

Artist IDs retain the existing deterministic name-derived `art_…` construction and, once registered, remain the permanent ID for that stored artist. **Global artist identity rename is not a currently supported operation and is excluded from v1** by coordinator scope decision. There is no new artist PATCH/name-rename endpoint, normalized-name alias table or lookup, identity-merge behavior, or change to pure artist_id_for_name. Existing normalization/manual-credit revision/preview/apply/undo semantics remain unchanged; do not edit dirty recommendation fallback keys or snapshots to accommodate a speculative feature.

Existing per-track/album credit changes and bulk one-to-many replacements edit memberships, **not global artist renames/merges**; they must not redirect an artist to a guessed first replacement. A registered artist left with zero memberships remains an authenticated empty profile at its original ID. Change only artist detail existence lookup to read the registered row even when catalog membership count is zero; normal catalog listings may continue excluding empty artists. No artist merge/delete API is introduced. Tests cover membership replacement and undo preserving old/empty share profiles, existing track metadata/album rename stability and album merge aliases; they do not claim support for a nonexistent global artist rename. A future global rename requires separately scoped identity/snapshot/recommendation design and review.

Unknown ID is 404; known explicitly deleted entity is 410; both show “Недоступно” with safe navigation. Do not leak existence to unauthenticated callers: authorize before registry lookup. Registry metadata has catalog-scale permanent retention because permanent-link correctness requires it; it contains no tokens or audio. Operational counts and growth are monitored; deleting aliases to meet a cache limit is prohibited.

### 7.3 Entity fetch contract

Existing authenticated APIs remain: `GET /api/tracks/{id}?credits_only=true` returns current serialized TrackDTO without editor file IO; `GET /api/albums/{id}` returns `{album:AlbumDTO,tracks:TrackDTO[]}`; `GET /api/artists/{id}` returns `{artist:ArtistSummaryDTO,popular_tracks:TrackDTO[],albums:AlbumDTO[]}` (retain any existing additive fields). Add required `share_id:string` to all three DTOs, `album_share_id:string|null` to TrackDTO, and nullable `content_version` to TrackDTO. `share_id` is the canonical lossless text encoding of the entity's ID; `album_share_id` encodes its current album ID. Existing `id` and `album_id` fields retain their legacy wire types, including numeric album IDs, so older clients stay compatible while updated clients use the lossless fields. Cover list/search/detail serializers as well as the new resolver; nested artist summaries also carry share_id. No signed stream URL in any catalog DTO. Baseline detail `/api/tracks/{id}` retains its editor semantics; share navigation must not accidentally invoke file mutation/reconciliation through that view.

Add `GET /api/share/{type}/{id}` authenticated, no-store, to centralize registry/tombstone resolution and avoid clients chaining alias guesses. It returns:

```ts
type ShareEntityResponse = {
```

## 9. Purge, retention and secret rotation

Purge is best-effort accelerated removal, never the authorization boundary. Separate **prepared versions** from **exposure ledger**. A hash, direct ticket, direct If-Match download, scan/import/edit or offline file does not create CDN exposure. Only immediately **before a CDN URL may leave the backend** commit `(track_id, hash, ever_exposed=true, max_expires_at=max(previous,new_expiry))` under the same track lock/fingerprint/access checks; if this commit fails, issue direct or fail busy, never emit an unrecorded CDN URL. A timed-out response after commit is conservatively exposed even if client receipt is unknown. Closed S5 signed fixture probes register the same exposure before handing out their URL. No raw token/URL or per-user ticket rows are stored.

At mutation time t define `drain_until = max_expires_at + 3600 + 30` (edge freshness allowance plus skew), and `needs_intent = ever_exposed && t < drain_until`. This is a conservative bookkeeping/backpressure window, not a claim of physical cache erasure or termination of open transfers. A tombstone/retirement always persists independently of this predicate. Only when needs_intent is true must deletion reserve `/cdn/audio/<track-id>/*` (all exposed versions/segments) or replacement `/cdn/audio/<id>/<old-hash>*` before destructive work; wildcard only at end, coalesce a track prefix instead of retaining every retired hash job. Expired/nonexistent exposure requires **no purge job/capacity**. Never-enabled deployments and direct-only tracks can edit/delete with purge disabled or outbox full, no accumulating optional jobs. New prepared hashes may remain direct; no hidden purge prerequisite for catalog publication.

During ordinary flag-off rollback, stop creating exposures immediately but retain/consume intents for existing exposures through their windows. Prefer leaving the purge consumer enabled to finish them; disabling it too leaves durable pending intent without pretending purge completed. Only mutations satisfying needs_intent can face capacity backpressure while old exposure drains. After all windows elapsed, catalog mutations no longer depend on the optional consumer/capacity. An expired unowned pending/failed job can transition to `drained` (not succeeded) with explicit `expired_without_confirmed_purge` metric/reason; preserve its audit record. No job is removed while its child/request is still live. Reissue of identical bytes later extends max_expires_at and reactivates exposure checks. A cached old capability can remain usable until its 1800-second expiry even if purge fails; open transfers/downloaded copies can outlive that. No request begun after signature expiry may receive cached audio.

Use a SQLite transactional outbox independent of cascaded track rows: job ID, dedupe path, state pending/submitting/polling/succeeded/failed/drained, attempt count, next_attempt_at, lease_until, fencing token, provider operation ID, sanitized reason. Commit **required exposed-version** intent with deletion/version retirement, reserve before filesystem replacement; startup reclaims an expired 60-second lease only after acquiring the actual process flock, never while a predecessor still owns an in-flight operation. §4.5 renews the lease every 10 seconds throughout submission/polling and governs shutdown/late completion. One existing-backend lifecycle consumer, no new system service or broker. Provider credentials have only needed resource/purge/operation-read permissions; secrets stay in restricted server storage.

Bound policy: at most **one purge submission every 65 seconds across all workers for the resource**, at most 10 deduplicated paths/batch, 1 concurrent submission/operation poll, request connect timeout 2 seconds and total 10 seconds. LRO polling at most once/30 seconds, maximum 15 minutes per submitted operation; a pending result after that is an explicit timeout failure, not success. Persist operation ID before polling; ambiguous network submission can be resubmitted idempotently as a purge, subject to the same limits. Batch coalesces retired versions under a track-wide prefix when necessary without purging unrelated audio.

Retry only transport errors, 429 and 5xx, max **5 submissions per job and 24 hours from first attempt**. Backoff at least 65/130/260/520 seconds with up to 20% positive jitter; respect Retry-After by taking the larger delay within the remaining 24-hour budget. 400/401/403/unrecognized resource are terminal immediately and alert; do not log provider bodies. Poll failed LROs/timeout can consume the next submission attempt. The persisted rate limiter also covers operator smoke/retry through this consumer; independent manual console purge must be coordinated in the runbook. After exhaustion state is failed, alert, select direct for new issuance until reviewed remediation; operator requeue is explicit, audited and creates a new finite budget. Audio still plays direct if control plane is down.

Outbox capacity is 10,000 unresolved path jobs (pending/submitting/polling/failed still within exposure window), reserved transactionally **only for needs_intent mutations**. At full, first coalesce existing same-track prefix or drain expired unowned jobs; if a genuinely exposed mutation still cannot retain its intent, return 503 before its filesystem mutation, rolling back the proposed tombstone/retirement in that same transaction. Disable new CDN issuance by breaker and alert, but **do not pause normal scan/catalog publication, direct-only mutations, unexposed tombstones or hash preparation solely due to purge capacity**. Existing tombstones/known in-window intents cannot be discarded for more work. Unmanaged missing/replaced files fail closed for origin and durably mark their already existing exposure-ledger row retired/reconciliation-needed even if outbox capacity is temporarily unavailable; no new URL under that stale hash, and the consumer materializes/coalesces the required intent when capacity frees. Existing authorized direct reads continue. Keep succeeded/drained outbox audit rows 7 days, terminal-failure history 30 days, outside active-capacity counting after drain; never claim drained means purge succeeded. Retired exposure/version rows expire only after no live intent/reconciliation/operation, 7 days after retirement and drain_until. Keep active version row, permanent entity aliases/tombstones and required mutation journals. Redacted operational logs retain 7 days, aggregates 30 days. Tests must prove never-enabled/consumer-off catalog mutations create zero outbox jobs, saturated exposed mutation backpressure, unaffected direct-only mutations, rollback with residual exposure and eventual drain/reissue.

Keep signing key, origin key and JWT secret independent. No CDN secrets in git, EXPO_PUBLIC/VITE settings, bundle, screenshots, shell argv, worker prompts or test artifacts. Restricted EnvironmentFile/secret store, mode 0600 or equivalent; existing S0 secret permissions need a reviewed operator correction, without incidental JWT rotation. Key procedures: first disable CDN issuance and increment epoch; signing rotation invalidates old CDN URLs (no dual-key overlap assumed), publish matching server/edge key, run closed tests, re-enable; clients spend bounded refresh then direct. Origin rotation: disable issuance, temporarily disable protected origin access while updating edge/backend together, validate cold fetch, re-enable; cached objects may still serve with valid signatures. A security incident also disables the media resource or rotates signing key; origin-secret-only rotation cannot revoke warm cache. No DNS/certificate removal as first action.
