## Sample-audio incident: scope and evidence

Before the test fixture was changed, the initial broad interrupted regression run, the subsequent `-x` run, and a single isolated album test ran the original `AlbumApiTest` fixture. It used `brain/temp_audio/Daft Punk - Around the World.mp3` as the source of `shutil.copy2` reads, and wrote copies under the same directory. The original test code has no direct write or delete operation on that source: metadata editing targets the destination paths. The first broad run was interrupted and did not retain per-test output, so the exact subset of successful copy or metadata-write operations cannot be reconstructed. Its progress had passed the album suite; the later `-x` output confirmed the merge case reached its first copy, and the separate merge test passed.

The complete set of fixed destination names used or removable by the fixture was `brain/temp_audio/alb_edit_1.mp3`, `alb_edit_2.mp3`, `alb_merge_1.mp3`, `alb_merge_2.mp3`, `alb_move_1.mp3`, `alb_move_2.mp3`, `alb_clear_1.mp3`, and `alb_partial_1.mp3` (all under `brain/temp_audio`). `copy2` could overwrite an existing destination, and the legacy per-test `tearDown` attempted to remove all eight names, not only those created by that test. There was no pre-run inventory of these names, so pre-existing files at them cannot be ruled out or restored, and the exact copies created, modified or removed cannot be independently proven. The current directory listing has no `alb_*.mp3` files. No additional cleanup was performed during this incident review; other files, including lock files, were preserved.

On inspection the source is 7,025,305 bytes, SHA-256 `0719f9a57da6ff4094ecb3084b5f5ee179e77e9a83116ef914285b55077bc687`, with mtime `2026-07-01 18:32:00 +0300` and ctime `2026-09-17 11:27:59.245833108 +0300`, both preceding the 2026-11-16 tests. That metadata and the fixture's source/destination operations support that it was not written by these tests, but there is no pre-run content hash or snapshot, so byte-for-byte original integrity is **not independently established**. The sample is ignored by Git and is absent from the CDN baseline manifest, so neither supplies an earlier hash. The later fixture generates a synthetic MP3 in a temporary directory instead.

## Implementation

Origin requests use a separate secret and strict path/query validation; direct playback remains supported, with HEAD, conditional transfer, Range and multipart handling. The path-policy ASGI boundary applies the media CORS and no-store policy to assembled-app success and error responses. Background version preparation and purge use durable state, exposure tracking, process ownership and bounded supervision. Migration 016 and Python backfill maintain permanent entity identity, track path claims, aliases and tombstones. Canonical ingest carries the returned identity through scan and recovery, and the authenticated share resolver emits filtered identifiers. Existing artist search now includes the canonical repository artist ID as `share_id`, an explicitly authorized minimal search-router addition.

During regression triage two compatibility defects were corrected: a legacy recovery lookup error now returns unavailable without attempting Qdrant, while deadline-bound errors still propagate; schema repair only runs the registry backfill when migration 016's registry exists, preserving old-schema migration tests. These changes do not relax identity or safe-path guards.

## Remaining gates and limits

Independent J3 review/tests must assess the complete contract and actual assembled implementation; a locally passing suite is not G2 acceptance. G3 still requires real cold/warm CDN token rejection, overwrite of client origin headers, query/cache-key isolation, origin routing and TLS, audio Range/conditional/CORS/browser no-store behavior, provider purge operation outcomes and both rollback procedures. Signed physical iOS build/device behavior, RF and European network measurements, pilot identity and disposable-fixture authorization, and the 24-hour pilot remain external gates. Keep issuance disabled until those gates and coordinator acceptance are complete. A purge or tombstone cannot revoke already transferred bytes or guarantee termination of an existing transfer.
