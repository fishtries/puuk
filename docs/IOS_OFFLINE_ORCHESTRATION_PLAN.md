# Офлайн на iPhone — план реализации для оркестратора и исполнителей

## Цель и решения пользователя

Владелец открывает Puuk в метро, включая запуск после перезапуска приложения. Ему доступны любимые песни с текстами, выбранные альбомы и плейлисты, подготовленная очередь «Моей Волны». Переход между связью и её отсутствием происходит внутри обычного плеера.

| Решение | Поведение первого релиза |
|---|---|
| Платформа | iOS. Изменения в brain нужны только при подтверждённом пробеле в существующем API. |
| Избранное | Скачивать всё автоматически, включая последующие лайки. При ограничении памяти показывать, сколько реально доступно. |
| Альбомы и плейлисты | Пользователь выбирает коллекцию для загрузки. Офлайн виден последний успешно сохранённый состав и порядок. При доступном сервере применять изменения. |
| «Моя Волна» | Автоматически держать запас впереди. Цель по умолчанию 60 минут, длительность выбирается в настройках. По исчерпании запаса продолжать скачанной музыкой. |
| Тексты | Первая по важности функция после воспроизведения. Сохранять доступные тексты и их тайминги заранее. |
| Оценки | Лайк и дизлайк действуют сразу. После подключения оценки и фактическое прослушивание должны учитываться рекомендациями. |
| Сеть | Скачивание по мобильной сети разрешено по умолчанию. Пользователь может выбрать только Wi-Fi. Начатые загрузки должны продолжаться при заблокированном экране. |
| Место | Пользователь выбирает общий лимит загрузок отдельно от длительности «Волны». |
| Следующая итерация | Поиск по скачанному имеет меньший приоритет. Вернуться к нему после приёмки основных сценариев. |

**Предлагаемые решения для исполнения.** Начальное значение лимита в ГБ пользователь не задал. Показывать объём избранного, когда его можно определить без скачивания, и доступное место. При дефиците первыми освобождать временные файлы завершённых задач, обычный кэш и прослушанный запас, затем сокращать будущий запас. Сохранять избранное и выбранные коллекции. При уменьшении лимита ниже их размера показать объём и предложить пользователю выбрать удаляемые загрузки или другой лимит. После возврата связи переходить от локальной подборки к свежей «Волне» на границе треков. Эти решения можно уточнить по результатам проверки на устройстве.

## С чего начинать в репозитории

Все пути ниже относительно корня. Перед назначением сверить текущую ревизию, локальные изменения и ближайший AGENTS.md. Ветки playback и доставки медиа могут развиваться параллельно.

| Область | Первая точка чтения | Что выяснить |
|---|---|---|
| Доставка аудио | app/ios/puuk-ios/shared/api/media.js, utils/audioCache.js внутри того же клиента | Версия контента, срок действия ссылки, признак допустимости кэширования, проверка длины, временный файл, публикация, отзыв и очистка. Текущий предел кэша 500 МиБ. Отделить бюджет коллекции от ограничений одной загрузки. |
| Плеер | app/ios/puuk-ios/utils/playbackCoordinator.js, preloadScheduler.js, networkPolicy.js и соответствующие тесты | Когда запрашивается источник, кто владеет очередью и отменой, как защищён активный файл, откуда приходят команды экрана блокировки. |
| Вход | app/ios/puuk-ios/App.js, features/auth/AppAuthGate.js, shared/api/apiCache.js | Восстановление последнего аккаунта и сервера, подтверждённый выход, смена пользователя во время загрузки. |
| Коллекции | app/ios/puuk-ios/features/library/, features/playlists/, brain/routers/albums.py, playlists.py, user_content.py | Полный список избранного с учётом пагинации, стабильные идентификаторы, порядок и повторы треков, точка входа альбома. |
| Тексты | docs/WORD_LYRICS.md, app/ios/puuk-ios/components/fullplayer/lyrics/ | Текущие формы ответа и правила выбора обычного, строчного LRC и проверенного пословного текста. |
| Рекомендации | app/ios/puuk-ios/shared/api/recommendations.js, brain/routers/wave.py, user_content.py, docs/TASTE_PROFILE_INTEGRATION.md | Запись оценок и контекста. В запросе wave feedback уже есть event_id и occurred_at. Проверить дедупликацию и взаимодействие с историей. shared/api/history.js служит точкой чтения недавних треков. |
| Сборка | docs/IOS_PLAYBACK_BUILD_INSTALL.md и app/ios/puuk-ios/AGENTS.md | Как воспроизводимо собрать клиент с нативной частью и поставить нужную ревизию на iPhone. |

## Контракт данных и поведения

Это требования к состоянию. Конкретный формат хранения выбирает старший исполнитель после осмотра существующих механизмов.

- **Локальная запись аудио** принадлежит аккаунту и серверу. Хранит стабильный ID трека, версию контента, локальный путь, проверенный размер, длительность, минимум метаданных для отрисовки. Временная сетевая ссылка может истечь до следующего запуска. Для чтения готового локального файла она не нужна.
- **Причины хранения** независимы. Один трек может одновременно принадлежать избранному, двум плейлистам, альбому и запасу. При снятии одной причины пересчитать остальные. Удаление защищать от гонки с воспроизведением, новой загрузкой и добавлением лайка.
- **Снимок коллекции** содержит её идентичность, название, упорядоченные элементы и отметку успешного обновления. Заменять список атомарно после получения всех страниц. Раздельно учитывать состав и готовность файлов. После успешного обновления новый трек виден со статусом загрузки. Ошибка обновления сохраняет последнюю целую версию.
- **Задание загрузки** проходит состояния «ожидает», «скачивается», «проверяется», «готово». У ожидания есть причина, например сеть или место. Хранить связь с системной задачей, версией и владельцем. После сбоя сверять очередь, реальные файлы и системные задания. Скачанный файл публикуется только после предусмотренных контрактом проверок.
- **Текст** имеет отдельную готовность. Различать сохранённый текст, подтверждённое отсутствие и прерванный запрос. Отказ при получении текста оставляет аудио доступным. Повторное открытие плеера без сети читает сохранённый текст с исходными таймингами.
- **Учёт бюджета** суммирует уникальные локальные файлы, тексты, обложки и обычный аудиокэш. Учитывать занимаемое место незавершённых загрузок и резервировать бюджет до параллельного старта. Физически свободное место ограничивает скачивание даже при большом пользовательском лимите.
- **Запас** измеряется суммарной длительностью следующих проверенных треков. Текущая песня, ожидающие файлы и уже пройденные позиции исключаются из показателя. Полная последняя песня может немного превышать целевую длительность.
- **Офлайн-действие** привязано к аккаунту и переживает перезапуск. Хранить итоговое состояние оценки и последовательность фактических событий проигрывания. Стабильный ID прослушивания создаётся один раз. Получение аудиофайла, предзагрузка и показ песни в списке сами по себе не образуют прослушивание.

## Порядок выдачи работы

Оркестратор сначала назначает S0. После утверждения форматов можно разделить независимые задачи. Для общих файлов playbackCoordinator, audioCache, App.js и нативного проекта назначать одного владельца интеграции на этап. Передавать младшим моделям входные примеры, путь вызывающего кода, состояния ошибки и проверку приёмки. Решения о хранении, нативном жизненном цикле и семантике серверных событий остаются у старших.

| Задача | Владелец | Зависит от | Что сдаёт |
|---|---|---|---|
| S0. Исследование | Senior iOS, оркестратор | Старт | Карта реальных вызовов, решение по локальному состоянию, исходные тесты и сценарий на устройстве |
| S1. Локальный путь воспроизведения | Senior iOS | S0 | Сквозной запуск одной сохранённой песни с текстом без сервера |
| S2. Фоновые загрузки | Senior iOS/native | S0, интеграция с S1 | Проверенная системная передача, восстановление и единая точка публикации файла |
| J1. Тексты | Junior iOS | Контракт S0, демонстрация через S1 | Хранение трёх форматов и чтение в полном плеере |
| J2. Коллекции | Junior iOS | Форматы S1 и очередь S2 | Избранное, снимки альбомов и плейлистов, обновление причин хранения |
| S3. Бюджет и «Волна» | Senior playback | S1, S2, J2 | Пополнение часа, вытеснение и переход к локальной очереди |
| S4. Оценки и история | Senior client/backend | S0, идентичность аккаунта из S1 | Долговечная очередь действий, повторная доставка и проверка серверного результата |
| J3. Интерфейс | Junior iOS | Контракты J1, J2, S3, S4 | Настройки, команды скачивания, готовность, состояния ожидания, обратная связь оценок |
| S5. Приёмка | Senior reviewer, оркестратор | Интеграция всех задач | Матрица ниже с результатами для проверенной ревизии и сборки |

### S0 и S1 — первый вертикальный срез

1. Проследить холодный запуск до восстановления профиля, открытия библиотеки, выбора трека, выдачи media ticket и старта аудио. Зафиксировать, где сегодня встаёт сетевой запрос. Отдельно проследить отказ API при рабочем интернете.
2. Выбрать место для постоянного индекса и его восстановления после незавершённой записи. Проверить установку поверх текущей версии: старый кэш либо безопасно переиспользуется после проверки владельца и версии, либо остаётся временным.
3. Провести один реальный трек через штатную доставку, проверку и локальную публикацию. В обычной библиотеке восстановить последнего пользователя, открыть карточку, получить локальный URI до вызова сетевого резолвера. Отсутствующий файл снять с готовности и запланировать восстановление при связи.
4. Проверить полное закрытие и запуск в авиарежиме, при недоступном сервере и при явном выходе. На смене аккаунта исключить поздний результат запроса старого пользователя. Сдать трассу проверок, включая отсутствие сетевого ожидания перед Play.

### S2 — загрузка при заблокированном экране

1. На установленной версии Expo проверить поддерживаемую системную фоновую передачу, получение результата после приостановки JS и восстановление по идентификатору. При пробеле предусмотреть небольшой нативный адаптер фоновой URLSession. Воспроизвести на физическом устройстве до массовой загрузки избранного.
2. Согласовать передачу с существующей выдачей медиа. При истечении ссылки перед стартом получить новую при разрешённой сети. Сверить версию файла перед публикацией. Если сервер обновил аудио, временную копию прежней версии не публиковать как новую.
3. Сохранить задания до старта, ограничить параллелизм, передать системе политику мобильной сети. При обрыве возвращать незавершённую работу в очередь с ограниченным повтором. Для уже готовых треков восстановление идемпотентно. При ручном закрытии продолжить сверку после следующего открытия.
4. Испытать скачивание плейлиста под блокировкой, возврат Wi-Fi, истечение ссылки, нехватку места и позднее завершение после выхода из аккаунта. Показать фактический размер и идентичность итогового файла. Поведение системных фоновых сессий описано в [документации Apple](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background).

### J1 и J2 — тексты и музыкальная библиотека

1. J1 получает от S1 идентификатор и версию трека, сохраняет существующий ответ текстов и подключает локальный источник к текущему экрану. Отдельные примеры для обычного текста, LRC, проверенного word-level, отсутствия текста и временной сетевой ошибки. После перемотки проверить позицию строки. Использовать действующий Contract v1.
2. J2 после успешного получения избранного вычисляет разницу с локальным набором. Пустой успешный список и обрыв на очередной странице имеют разный результат. Согласовывать с локальными оценками S4 до удаления причин хранения.
3. В меню альбома и плейлиста добавить операции постановки и снятия загрузки через единый интерфейс. Сохранить порядок песен, включая повторы, с одной физической копией аудио. Удаление с устройства сохраняет серверную коллекцию. Проверить общий трек в двух коллекциях, удаление одного плейлиста, офлайн-лайк на треке из «Волны».
4. Для частично скачанной коллекции вернуть экрану готовое количество, общее количество и доступные позиции. Если оборвалась двенадцатая загрузка, первые одиннадцать сразу играют после перезапуска.

### S3 — пополнение, освобождение места и воспроизведение

1. Получать рекомендации через действующий API и сохранять упорядоченную очередь. Планировать сначала ближайшие песни, затем остальной запас и фоновую догрузку избранного. Проверить, что большая коллекция не оставляет «Волну» пустой и постоянное пополнение не останавливает скачивание избранного.
2. Пересчитывать остаток после перехода, пропуска, удаления и изменения настройки. Объединять задания со штатной предзагрузкой по треку и версии. Если кандидатов мало или мешает лимит, показывать фактическое количество минут.
3. Когда связь пропала, воспроизводить готовые песни по порядку. После исчерпания перейти к доступной коллекции, исключить дизлайки и избегать недавних повторов, пока есть выбор. Если играть больше нечего, завершить очередь с понятным состоянием. При возврате связи обновить рекомендации с учётом ожидающих оценок без обрыва текущей песни.
4. Согласовать действия при уменьшении лимита, очистке обычного кэша, удалении коллекции и воспроизведении последнего оставшегося файла. Проверить конкуренцию двух загрузок за оставшееся место.

### S4 — передача обратной связи

1. Проследить обычный лайк, дизлайк, снятие оценки, skip и finish от клиента до профиля рекомендаций. Использовать существующие серверные операции по их реальной семантике. В действующем wave feedback допустимы like, skip и finish. Для дизлайка есть маршрут user_content.
2. Сохранять локальное изменение оценки и намерение отправки согласованно. Последовательность «лайк → снять лайк» приводит к последнему состоянию. После восстановления связи сначала согласовать действия, затем обновить избранное и будущую очередь. Дизлайк скрывает песню из локальных кандидатов сразу.
3. Для фактических прослушиваний передавать исходное время, контекст, длительность и стабильный ID там, где поддерживает действующий контракт. Разобрать случай «сервер применил, ответ потерялся». Проверить серверную дедупликацию, лимит запросов и отсутствие двойного положительного сигнала из истории и feedback. Если конкретному пути нужна доработка brain, описать минимальное изменение и совместимость действующих клиентов.
4. Проверить перезапуск с несданными действиями, смену пользователя, удалённый на сервере трек и временные ошибки. Ошибка одного элемента допускает обработку остальных. Результат сверить по данным сервера и входам профиля рекомендаций.

### J3 и S5 — интерфейс и интеграция

J3 получает готовые селекторы состояния. Показать раздел «Скачанное», прогресс коллекции, фактически готовые минуты «Волны», объём на устройстве и причину паузы. В настройках дать отдельные элементы управления общим лимитом, длительностью и сотовой сетью. Проверить экран с частично готовой коллекцией, пустую библиотеку без сети, длинные названия и VoiceOver. Визуальные решения сверить с docs/design/DESIGN.md и руководством iOS.

S5 собирает все изменения в одном кандидате. Запустить затронутые Jest-наборы из app/ios/puuk-ios через npm test -- --runInBand с именами наборов. При изменении brain выполнить профильные pytest с PUUK_DB_PATH на временной БД. Примеры существующих наборов: audioCache, preloadScheduler, playbackCoordinator, AppAuthGate, test_taste_profile.py. Зафиксировать модель iPhone, версию iOS и идентификатор сборки для сценариев ниже.

## Матрица приёмки

| Условия и действие | Наблюдаемый результат |
|---|---|
| Скачать песню с текстом, закрыть Puuk, включить авиарежим, открыть из библиотеки | Песня сразу играет, доступен верный текст, перемотка сохраняет синхронизацию. |
| Интернет есть, brain недоступен | Открывается библиотека последнего аккаунта, Play не ждёт ответа API. |
| Выбрать длинный плейлист, заблокировать экран до окончания части загрузок | Системные передачи продвинулись под блокировкой. После разблокировки число готовых файлов подтверждается воспроизведением без сети. |
| Отключить мобильные загрузки и уйти с Wi-Fi, затем вернуть Wi-Fi | Фоновые скачивания ожидают разрешённую сеть, уже сохранённая музыка играет. Очередь продолжается без повторной команды. |
| Изменить плейлист на другом устройстве, открыть офлайн, затем восстановить связь | Видна старая полная версия, затем новая с правильным порядком и прогрессом новых треков. |
| Прервать обновление списка или скачивание файла, перезапустить приложение | Снимок целый. Частичный файл не помечен готовым, завершённые треки доступны. |
| Иметь запас меньше цели, потерять сеть и проиграть его до конца под блокировкой | Переход к скачанной музыке с рабочими кнопками управления. Возврат связи не прерывает текущую песню. |
| Поставить лайк на треке запаса, дизлайк на другом, несколько раз оборвать отправку | Первый трек закреплён и добавлен в избранное, второй исключён из подбора. Сервер получил итоговые оценки, история и профиль не удвоили событие. |
| Израсходовать лимит, уменьшить его ниже размера коллекций и увеличить снова | Объём общих файлов посчитан один раз. Видно, что ожидает места. После увеличения оставшиеся загрузки возобновляются. |
| Очистить временный кэш или удалить один из двух скачанных плейлистов | Любимая песня и трек другого плейлиста продолжают играть. |
| Сменить аккаунт во время передачи и доставки оценок | Поздние события и файлы старой сессии не появляются в новом аккаунте. |
| Обновить приложение поверх прежней версии и отдельно проверить обычный онлайн-стриминг | Старт, сетевое воспроизведение, существующие тайминги и управление плеером работают. |

## Передача результата оркестратору

Для каждой задачи передать ID, базовую и итоговую ревизии, изменённые файлы, фактический путь пользовательского действия, выполненные проверки, их результаты и оставшиеся ограничения. Если результат расходится с контрактом, указать сценарий воспроизведения и владельца исправления. Для фоновой передачи, холодного запуска и экрана блокировки отдельно указать фактическую проверку на устройстве. При отсутствии iPhone отметить эти строки как ожидающие проверки и продолжить независимые задачи.

Оркестратор сверяет каждое решение пользователя из первой таблицы с интеграционным сценарием, учитывает изменения соседних веток и возвращает конкретные несоответствия владельцу задачи. Итоговый отчёт связывает сборку с результатами матрицы, отдельно перечисляет отложенный поиск и принятые в ходе реализации продуктовые решения.
